# Experiments

Each directory here is a feature you can run on an X-M1 from RAM: a `hooks.json` naming stock functions to run in front of, and a `lib.rs` and/or C and assembly with the handlers. [`hello`](hello/) is the template and [`sdk`](sdk/) the shared header and linker script. [Build and test your own X-M1 feature](../docs/experimenting-on-your-x-m1.md) walks through writing one, trying it in the emulator and pushing it to a camera.

`playback_owned` is an emulator-only replacement package for the existing owned playback source/mode preparation pair. Its explicit `replace_entry` hooks publish ordinary A32 entry functions instead of observation trampolines. Each declaration binds the exact X-M1 1.50 entry, extent, source hash and handler; the live experiment payload selector refuses these hooks. Omitted hook modes retain the existing Observe behavior.

Build `//replacement/playback:playback-owned`, then select `--ram-push-e2e --fujimod --experiment playback_owned` in `//emulation:xm1-viewer` with the identified virtual card. Installation writes an artifact-keyed installed checkpoint before the trajectory. `//emulation:media-route-smoke --installed DIR --owned-playback LINKED_PACKAGE_DIR --route play` restores that checkpoint, verifies live publications and immutable runtime bytes, and observes owned entry execution with the original preparation bodies excluded. It retains complete expected/actual runtime bytes and admits only the declared ABI 7 rendezvous/mailbox scalar fields as installation-time changes, with a successful install and matching completed peer nonce required. Publication tables, padding, entry code and callback code must match the package. The complete runtime remains write-protected over the observed PLAY interval. Installer callbacks and their storage remain retained; this is not callback retirement or unload qualification. The normal SDK, card, firmware, NAND, ROM, output and checkpoint identity options still apply. The package directory contains `runtime.bin`, `kernel.elf`, `experiment.json` and `ram-push-manifest.json` from the actual relinked installation.

`//replacement/playback:qualify --runner NATIVE_RUNNER --package LINKED_PACKAGE_DIR --output NEW_DIR --native-jobs 1` exercises those exact linked runtime bytes against the original preparation entries. Its native retained-dispatch/output/preset stubs define the service boundary; actual machine actions and media/output behavior belong to the installed PLAY run. The pair's [contract](../replacement/playback/contract.json) names the retained router, dispatcher, globals and service shims. This package does not qualify whole playback, unload or a camera operation.

The same qualifier with `--mode-callers` before `--runner` selects separate conditional native boundaries: the actual stock UI machine-5 action, its `0x0142` packet producer and queue-4 descriptor builder; and the retained machine-1 mode actions through the actual installed entry publication. The producer checks its emitted descriptor/payload, status and error-report ordering. The entry-caller cases check the full retained-dispatch return, machine-11 event and machine-1 cursor against the original bodies. Retained token/task/queue/error and dispatch/output/preset services remain declared boundaries. A missing natural USB/application-mode producer cannot be replaced by this conditional result; the integrated JPEG pair gate remains separate.

Each native qualifier run records its own executable digest and complete arguments before executing cases.

`//emulation:playback-mode-observe --sdk STORE --bridge-sha256 HEX --installed DIR --owned-playback PACKAGE --output NEW_PRIVATE_DIR` selects the separate natural USB/application-mode experiment. It requires a freshly keyed installation on a bridge exposing the existing modeled Cable and enumeration operations. It writes only the volatile configuration byte `0xf7`, checks the complete 256-byte readback window, closes the virtual protocol session, detaches and reattaches with one existing 40-million-instruction window per edge, then attempts ordinary enumeration with a 90-million-instruction activation cap. Installed artifact checks and the source/mode execution watch bound this interval. Its mode-consumer result requires the actual UI machine-5 producer and retained caller, and remains separate from JPEG pair acceptance.

The natural observer's retained-caller entry/return traces capture the message header and payload pointer, machine-1 cursor, machine-11 event and full `r0`. Its gate requires message `0x0142` and the caller's observed cursor/return relation.

Driver snapshots read the adjustment-cache pointer and `0xf7` byte, phase `0x0146a180`, completion handle `0x0146a090`, observer slot `0x0146a0e4`, boot presence `0x00914828` and USB-manager latch `0x015c229c`. Controller traces include the phase compare at `0x00d81d18`, whose preceding literal load is `0x01469cd0 + 0x4b0`.

Finish `0x01220238..0x0122026c` needs separate conditional coverage unless naturally observed. JPEG lifecycle qualification does not require mode-entry execution or qualify the separate preparation pair, natural USB/application-mode transition, pixel fidelity, capture continuation or unload.

The preserved preview and full source spans are both baseline 8-bit three-component JPEG with 4:2:2 sampling, independently inspected with ExifTool.
