# Bounded C native-function harness

The runner uses Unicorn's C API and a closed Cortex-R5F ARM/little-endian profile for synthetic and admitted stock cases. Unicorn has no Cortex-R4; R5F is its closest model to the ARMv7-R, PMSAv7, VFPv3-D16 core inferred for the X-M1 in [E-CPU-PROFILE](../reports/firmware-extraction.md#cpu-profile). Nothing may depend on R5F-only behavior ([rule](../docs/principles.md#scope-and-evidence)); the runner rejects A32 SDIV/UDIV, and coprocessor exclusion keeps R5F ID, MPU and TCM/cache registers out of reach. Synthetic fixtures supply no X-M1 behavior or ABI evidence. No camera is enumerated or opened. `unicorn-info.c` remains the smaller engine-initialization check. Follow [phase 3](../spec/03-phases-and-gates.md#3b-native-function-harness) and the [runtime contract](../spec/08-artifact-and-runtime-contracts.md). The implemented C engine boundary and retained host C models do not establish a general C policy; [current principles](../docs/principles.md#implementation-and-build) govern new implementation and migration.

```sh
devenv shell -- bazel test //emulation:native-runner-tests
devenv shell -- bazel build //emulation:native-runner
devenv shell -- bazel run //emulation:native-case -- --runner bazel-bin/emulation/native-runner emulation/fixtures/arithmetic.json
```

The last command prints a JSON report and returns zero only when the exact expected registers, complete final memory and stub events match the expected exit. A negative fixture can pass by reproducing its independently expected guard failure; inspect `runner.status` alongside the outer validation status. Redirect reports into an explicitly chosen local artifact directory when retaining a run. [Fixture provenance](fixtures/PROVENANCE.md) derives the expected results independently of execution; `devenv shell -- bazel run //emulation:generate-fixtures -- --output /tmp/fuji-native-fixtures` writes a new directory with exact binary bytes and structurally identical JSON manifests. Canonical Haskell serialization changes JSON whitespace/key ordering; the original checked-in manifests keep their historical formatting.

## Case contract and execution authority

[Native-case schema v1](../schemas/native-case.schema.json) precedes the consumer. The Haskell `native-case` adapter uses pinned Aeson, shared strict JSON guards and the trusted host `sha256sum` executable to reject duplicate/unknown fields, unsupported profiles, non-regular files, bad hashes/slices, overflow/overlap, unsupported permissions/state, invalid expectations and zero budgets. Artifact paths stay beneath the physical case directory. It verifies each complete artifact's exact SHA256, then sends the same observed bytes and declared slices in a bounded text wire to C; C never reopens artifact paths. This small host adapter avoids adding a target JSON/crypto dependency. The C engine is the execution authority and independently checks its closed wire version, all addresses/lengths, permissions, logical containment, stack/state, functions/stubs, and nonzero limits, including malformed direct wire.

All r0–r12, SP, LR and CPSR are supplied. CPSR admits user ARM mode with explicit NZCV flags only; entry and LR/exit are separate explicit addresses. The stack top is eight-byte aligned inside writable memory. Regions carry `r`, `rw` or `rx` permissions; each region's bytes are zero-initialized explicitly or come from an exact artifact slice with explicit zero-filled remainder. `rx` regions must end at or below `0x7ffffffc`: the MPU stays disabled, the PMSAv7 default memory map is execute-never from `0x80000000` (on an R4F too), and the four-byte margin makes running off a region's end report `fetch_guard` rather than an abort. Every transitive function starts at an allowlisted address and has a nonoverlapping bounded executable range. ARM BL/BLX-register calls are tracked to declared functions or register-only stubs; B/BX tail transfers to declared functions retain the current call frame. Returns use BX LR or LDM with PC naming the recorded return address or exit sentinel. Thumb and untracked PC-loading returns are excluded. Register-only stubs require exact named input values and explicit r0–r12 outputs, change LR to the return address, and emit exact input/output events; unknown targets and mismatched inputs fail.

Unicorn requires page-aligned backing, but the runner's logical regions can start/end inside pages. Hooks reject every executed fetch or access that lacks logical containment/permission. Stopping inside a valid Unicorn write hook can still commit the current store. The runner therefore preflights **every admitted memory instruction before execution**: immediate-offset ARM LDR/STR byte or word; immediate-offset LDRH/STRH, including supported pre/post-indexed writeback; pre-indexed register-offset byte/word/halfword transfers with optional writeback and immediate LSL/LSR/ASR shifts for byte/word forms; pre-indexed immediate LDRSB/LDRSH without writeback; immediate pre-indexed LDRD/STRD with optional writeback; ordinary LDM/STM; PC-relative and register-base load-to-PC dispatch; and tracked LDM returns. It rejects misalignment, positive address carry, cross-boundary access, unsupported PC operands and writeback-base aliasing before any transfer. U=0 subtraction wraps modulo 2^32 before containment checking. Dispatch entries must be four-byte-aligned ARM targets contained in the current function; returns must name the recorded return or exit sentinel. Register-specified-shift and ROR/RRX offsets, post-indexed register-offset forms, unprivileged transfers, atomic/banked transfers, system/PSR writes, coprocessors and other memory forms remain excluded. Register-only MOVW/MOVT, UXTB/UXTH/SXTB with ROR #0/8/16/24, UBFX/SBFX/BFI/BFC, MUL/MLA without S, and tracked BLX calls are admitted subject to their operand/field restrictions; immediate and register tail transfers preserve the tracked call frame. Shared-page RX/RW and multi-store failure fixtures require unchanged protected bytes. Memory hooks remain a second guard and access log; backing pages do not grant guest access.

The C runner checks every Unicorn error-returning call and exact header/runtime version, traps interrupts, and imposes instruction and monotonic wall deadlines plus Unicorn's wall timeout. The adapter adds a process timeout, an 8 MiB cap per stdout/stderr stream, process-group termination and bounded reaping, and preserves partial diagnostics if the engine stalls. Compiled adapter limits are 16 logical regions, 4 MiB total logical bytes, 160 functions, 32 stubs, 512 expected events, 1,000,000 instructions and 10,000 ms. Artifacts are each at most 4 MiB (20 maximum); JSON input is at most 16 MiB. The engine-private wire accepts up to 512 stub definitions, but the public adapter does not expose that capacity. The checked-in v1 schema still has narrower 1 MiB/32-function/32-event/16-artifact bounds; a case accepted by the compiled adapter can therefore fail schema validation. This contract gap is not permission to widen safety limits. The C wire is private v1: profile/header and limits, 16 initial register values, bounded region/function/stub counts, exact region hex bytes, function ranges and indexed register stub bindings, with no trailing tokens. All numbers are bounded before conversion/allocation.

Load-to-PC table entries are validated before execution: both register-base and PC-relative dispatch refuse targets with either low bit set. Every code hook also refuses CPSR.T. This prevents a 32-bit Thumb instruction from being interpreted as an A32 conditional instruction and executing outside the profile's preflight.

## Outputs and limitations

The report identifies the exact case, verified artifacts, wire and runner by SHA256. It preserves full register/final logical memory state, instruction count, monotonic elapsed nanoseconds, Unicorn version/error, stub events and the last 64 instruction/access records. `trace_total` and `access_total` expose truncation; access values are meaningful for writes, while read/fetch hook values are unspecified. Expected memory spans define the entire permitted final change set; every undeclared byte must equal its initial value. A normal return alone cannot satisfy a fixture. Invalid case, runner error, expectation mismatch and external timeout all exit nonzero with diagnostics.

`memory_provenance` retains the first 4096 valid logical read/write events in execution order, with the instruction PC, instruction word, address, width and value. Read values are sampled from emulated memory rather than Unicorn's unspecified read-hook argument. Write values are sampled at the pre-store hook. `memory_provenance_total` exposes truncation; a provenance experiment must reject a truncated log. Guard-rejected accesses remain in `accesses`, not `memory_provenance`. These are emulation events, not silicon bus observations or an automatic taint analysis.

This subset models no X-M1 stock ABI, exceptions, peripherals/MMIO, scheduler, interrupts, DMA, caches, coprocessors or hardware timing. Extending an ISA/profile requires preflight for every newly admitted memory/state operation and independent fixtures. A stock case (`origin: "stock"`) is admitted only with an independently known result and exact input provenance; the CPU family remains static inference only. D-01's host preparation is tested and one stock path is reproduced in the next section, accepted for G3 on 2026-10-08. See the [validation scope](../reports/validation.md) and [evidence ledger](../docs/evidence.jsonl).

Stock cases below require owner-supplied proprietary decodes or body captures; they are not bundled redistributable fixtures. Public [record-acceptance and custom-continuation findings](../reports/adjustment-and-service-interfaces.md#record-acceptance-and-custom-continuation) retain the area-2/area-3 interface analysis behind the private provenance notes.
