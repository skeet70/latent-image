# Synthetic native fixture provenance

The original Python generator is preserved in repository history. The current Haskell [`GenerateFixtures.hs`](../GenerateFixtures.hs) encodes the independent words/expectations and writes a new output directory. Generated binaries are byte-identical to the checked-in ones and generated JSON values match structurally; canonical serialization changes JSON formatting/key order. The original manifests that survive keep their historical formatting; `movw-movt`, `unsupported-psr-immediate`, `unsupported-arm-divide`, `fetch-execute-never-boundary`, `uxtb`, the `register-offset-byte*` trio, the `pop-pc-return`/`unknown-pop-return` pair, the `register-offset-word*` pair, the `halfword*` pair, the `jump-table*` trio and the `unsupported-register-offset-*`/`unsupported-halfword-*` refusals were written by the Haskell generator. The 2026-10-08 admission widening replaced `unsupported-register-offset` and `unsupported-halfword`, whose immediate forms are now admitted. The 2026-10-09 widening added the register-offset halfword, UBFX, MUL/MLA, UXTH/SXTB and BLX-register fixtures below and retired `unsupported-halfword-register`, `unsupported-multiply` and `unsupported-mode-switch`.

All `.bin` files in this directory were authored for host tests, not obtained from any Fujifilm camera, firmware container, sibling-camera example, dump, compiler, or emulator. The addresses are arbitrary synthetic values. The generator encodes the listed 32-bit ARM instruction words in little-endian order and hashes their exact bytes. JSON manifests name every artifact hash and byte slice. Expected values below were derived directly from integer arithmetic and instruction semantics before execution; the generator does not execute code or generate expectations from runner output.

The profile selects Unicorn's Cortex-R5F in ARM mode with CPSR `0x00000010` (user mode, zero arithmetic flags). The model follows the X-M1 1.50 CPU-family inference in [E-CPU-PROFILE](../../reports/firmware-extraction.md#cpu-profile); these fixtures still make no X-M1 behavior or ABI claim. Registers r0–r12, SP, LR and CPSR are initialized. SP is `0x3020` at the end of a 32-byte writable stack. LR and the exit sentinel are `0x1080`; the sentinel's four executable bytes are explicitly declared and never executed. Code starts at `0x1004`, deliberately inside a page. Four-byte mutable data starts at `0x2004`. Remaining registers and explicitly declared zero-filled bytes start at zero. Flags remain unchanged because arithmetic uses ADD rather than ADDS.
