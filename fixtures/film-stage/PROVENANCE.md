# Film-stage oracle fixtures

Expected outputs of the EXR Processor II film-stage model (`//host:film-model`, `FujiAF.FilmStage.develop`) on synthetic parameter sets. The test `//host/firmware:film-stage-tests` checks the model against them. Evidence scope: agreement of two implementations of the arithmetic x70view documents for the X70 RAW conversion on flat input; it says nothing about X-M1 hardware.

## Parameter sets

All values are invented for this fixture; none is read from firmware or camera data. The tone exponents `[2,2,3,4,5,5,5,6,6]` are the segment layout of the record format.

| File | Construction |
| --- | --- |
| `identity.params.json` | gain table 512 (x1); identity matrix and chroma; tone points `min(16383, round(4 (s_k + j w_k / 3)))` for segment start `s_k` and width `w_k = 16 << e_k`, j = 0..2, last point 16383 (linear 12 to 14 bit); five bands of gain 256, shift 0, bounds 64, 128, 192, 255 |
| `synthetic-a.params.json` | gain table `512 + round(400 exp(-i/6))`, i = 0..21; matrix `[[1400,-300,-76],[-120,1250,-106],[60,-460,1424]]`; tone points `round(16383 (i/27)^0.45)`; chroma Cr from R-Y 1500, Cr from B-Y -120, Cb from R-Y 250, Cb from B-Y 1800; bounds 50, 110, 190, 240 with (shift, gain) (100, 200), (30, 240), (0, 256), (-80, 320), (-300, 500) |
| `synthetic-b.params.json` | field-range stress: gain table alternating 1600 and 300 with 8191 at entry 11; matrix `[[3000,-1500,-476],[-900,2500,-576],[-1000,-2000,4024]]`; tone exponents `[3,3,3,3,4,4,5,6,6]` (segments end at input 3584) with non-monotone points `(4099 i) mod 16384`; chroma -2000, 4095, -4096, 3000; equal and end bounds 0, 128, 128, 255 with (shift, gain) (-1024, 1023), (1023, 0), (500, 700), (0, 0), (-500, 900) |

## Input grid

`FujiAF.FilmGrid.oracleGrid`: 6848 white-balanced 14-bit RGB triples, 1728 from 12 levels per channel, 4096 uniform and 1024 log-spaced from a seeded 32-bit LCG. Written as u16 LE R, G, B by `classic-chrome-model oracle-input`; SHA-256 `2296b4b06ab925178e44af028c417d20494fca4945b5eb6143fe45ad490b7aa9`.

## Oracle outputs

`NAME.ycc` holds u8 Y, Cb, Cr per grid point from `develop()` in jitl's x70view `emulator/film_stage.py` (revision `a47591d9bdd94ab6e23b3e0a8e91c3cebaea4f16`, file SHA-256 `89fc51f3082f3cf1b8d20ecd453bc1d730c78bcaa15e8ba49bad57a9e1849b58`), run in place in x70view's own environment on the register words `classic-chrome-model oracle-input` writes:

```sh
classic-chrome-model oracle-input OUT identity=identity.params.json synthetic-a=synthetic-a.params.json synthetic-b=synthetic-b.params.json
cd x70view && .venv/bin/python -c "import sys,json;sys.path.insert(0,'emulator');import numpy as n,film_stage as f;g=n.fromfile(sys.argv[1],'<u2').reshape(-1,3).astype(n.int64);r={int(k):v for k,v in json.load(open(sys.argv[2])).items()};n.stack(f.develop(r,g),-1).astype(n.uint8).tofile(sys.argv[3])" OUT/grid.u16 OUT/NAME.words.json OUT/NAME.ycc
```
