## Target and acceptance

The menu subsystem's target is the one #128 names: a declarative menu tree, one owned menu engine, the nine generic widgets, a typed settings service and a render layer, with stock modal dispatch reduced to a thin event adapter. This document designs the engine and the part of the tree it consumes. Widgets, the settings service (#127, `replacement/property_service`) and the render layer are consumers or providers at the engine's boundary, not part of this unit.

Acceptance, from #128: for the observed presses (E-MENU-ENGINE-OBSERVE-150) and the picker pairs (E-MODAL75-PICKER-PAIRS-150), the owned engine produces the same globals, snapshots, event-`0x1d` posts and ordered settings writes as stock, and render-compares equal.

## The stock engine this replaces

Facts from E-MENU-ENGINE-OBSERVE-150, `reports/recipe-bank-ui-ownership.md#stock-menu-engine-and-the-owned-target` and the review of revision 1.

- Events cross one fixed block `0x0094f64c..0x0094f660` written by `0x0063270c`: code, kind, node, id, extra. Stage events have code `0x1e` and are posted through `0xd3d858(kind, id)`.
- Four stage consumers call `0xd4dd2c`: `0xca4674` (controller 100), `0xca0080`, `0xca4e98` and `0xcc45ac`. `0xca4674` saves the 0x430-byte block (`0x0061d384`), calls `0xd4dd2c`, restores the block (`0x0061d3a8`) when the engine returns 0, then runs the special post `0xd42a64` and, for kinds 4, 5 and `0xe`, the value post of event `0x1d`. `0xd4dd2c` does work of its own before and after the engine (`0xd4d7a4`, `0x0063807c`, copies of `0x944580` and the event block).
- `0xd4dd2c` calls the engine wrapper `0xbf95c8`, which calls the kind switch `0xbfa234` and then the snapshot store `0x0061ceac(*0x009571d0)`, also when the switch returns 0. `0xbfa800` (open and re-open, reached by kinds 1, `0x13` and every push and pop through `0xbfab98`) also calls `0xbfa234` directly.
- Kinds (`0xbfa234`, all.c:331301): 1 open, 2 close, 4, 5 and `0x45`..`0x48` move, 6..`0xb` a move wrapped in a pop and push, `0xe`/`0xf` push and pop, `0x10`..`0x12` multi-level push and pop, `0x13` re-open. Each kind branches further on its arguments and node flags: a move whose id equals the node's rows per page is a page move; push and pop with ids `0x17`/`0x18` seek through `0xbfad04`; a parent of type 5 or 7 changes push and pop; kind 1 on an empty node recurses into kind `0xf`. Kinds 1, 4, `0xe` and `0xf` were observed, each in one argument class.
- Engine state, the block `[0x009571d0,0x00957600)`: open node pointer `0x009571d0`; node word 10 (`*(u16 *)(record + 0x28)`, written by `0xbf976c`) at `0x009571d4`; cursor `0x009571d8`; visible ordinal `0x009571dc`; visible count `0x009571e0`; scroll top `0x009571e4`; total rows `0x009571e8`; visible count at open `0x009571ec`; row states `0x009571f0[0x4f]` (0 offered, 1 variant, 2 disabled, 3 hidden); saved cursor, ordinal and count from `0x0095732c`; remembered rows `0x0095733c[node]`; cursor stack `0x00957554` indexed by depth `0x009575f4`, with the visible count saved on pop at `0x0095757c`; the push classifier save `0x009575f8` (`0x0061d0e4`); menu-open flag `0x009575fc`.
- Outside the block, the move `0xbf9f44` stores the moved row's class and token at `0x01467580`/`0x01467584` (all.c:331291); the special post `0xd42a64` posts `0x1d` from them for kinds 8..`0xb`, and `0xcc453c` reads them.
- Snapshot stores: `0xbf9f44` at the event's node index, `0xbfab98` at each new record id at each depth it passes, `0xbf95c8` at `*0x009571d0`. Areas `0x00944414` (root), `0x0093eb74+0x2c*id` (depth 1), `0x009412d4+0x2c*id` (depth 2). Registry index and record id differ for some nodes (`0x78fdd4` is registry 82 with id 63).
- Initial row: `0xbfa800` sets the cursor from `0xd588b8(kind, node, class)` (all.c:331505); its default arm reads the property's current value (`0x0061c93c`) and converts it to a row token (`0x0061d514`), and its class-5 arm reads the block.
- The engine calls `0xd5b350` on open, close, move, push and pop (which calls `0x00637ed0`), `0xd52684` for row states, and `0xbf9a5c` writes property `0x285` through `0x0061c91c` for node `0x7a` (all.c:330959).

## Engine boundary

The engine is a `no_std` Rust library (`replacement/menu_engine`) whose core holds no stock addresses. Its one operation runs an event on the in-progress state in place and makes every call into stock through a trait, in stock's order.

```text
apply<S: EngineServices, P: DerefMut<Target = EngineState>>(tree: &Tree, state: P, event: MenuEvent, services: &mut S) -> Result<EngineResult, NotOwned>
```

`P` is the one in-progress state: a `&mut EngineState` on the host, and in the guest a zero-sized `StaticState` handle on the adapter's `ENGINE_STATE`, so no frame holds a copy of the state.

- `MenuEvent` carries every argument a kind uses: `node: StageNode`, `id: StageId`, `extra: StageExtra`, decoded into typed variants (`Open`, `Close`, `Move { direction, step }`, `FrameMove`, `GroupMove`, `Push`, `Pop`, `MultiLevel`, `Reopen`, `Unknown`), each keeping node, id and extra as the kind reads them. A move's `step` distinguishes a row step from a page step (id equal to rows per page).
- `EngineResult` is `Accepted` or `Rejected`, the value `0xd4dd2c`, the bracket, `0xd42a64` and the value post branch on.
- `NotOwned` names why an event falls back. `apply` returns it only before its first service call: the class, the block's total against the open node's tree rows, the node it opens (type, `Wrap::Wraps`, queried availability, 1..=`0x4f` rows, restored cursor below `0x4f`), a push target that is a package node, and the stack bounds are all decided first. After that the event always completes.
- `EngineState` is the typed form of the block plus the last-move pair `0x01467580`/`0x01467584`: open node, `NodeWord10`, the live cursor frame (cursor, visible ordinal, visible count, scroll top), `RowCount`, the visible count at open, `RowState` per row, the saved frame, the remembered-row table, the cursor stack and its depth, the push-saved classifier, `MenuOpen`, and `LastMove { class, token }`. The push-saved classifier is computed by the engine from the in-progress parent state, as `0xbfab98` evaluates `0x0061d0e4` after `0xbf9a5c` and before switching nodes (all.c:331566), using the classifier and snapshot shared with `owned_menu::frame` in `menu_engine/src/frame.rs`.
- `EngineServices` is the trait for stock. Before each call the adapter writes the words of the in-progress state that differ from the block and the last-move pair, since the stock functions read them.
  - `perform(state, Effect)` performs one effect at the point stock does: `Notify` (`0xd5b350`), `StoreSnapshot { depth, slot, record }` carrying the 44-byte record `0x0061cd14` would write at that step, and `StoreFromBlock { slot }`, which runs the owned `0x0061ceac` over the block where the engine cannot compute the record: after a stock call replaced the state, or where the record reads past the tree's rows. Order matters: `0xbfab98` notifies before `0xbfa800` asks for availability (all.c:331598-331604), and for a pop the notification reloads the settings image (`0x00637ed0(1)`, all.c:551880-551905).
  - `availability(state, class, token) -> RowState` (`0xd52684`, one row per call as stock calls it) and `initial_row(state, kind, node, class) -> Option<RowToken>` (`0xd588b8`, which returns `0x7ffffffe` for no selection, after which `0xbfa800` keeps the restored cursor; all.c:331506, 550703).
  - `kind_switch(state, call)` and `seek(state, call)` tail-call stock `0xbfa234` and `0xbfad04`, decode the block afterwards back into `state` and return the function's result. The engine uses them where stock calls them after the engine is committed: `0xbfa800`'s empty arm, which pops through the kind switch when no row is selectable and the node has a parent (all.c:331458-331465), and `0xbfad04`'s pop or push again when the node that pop lands on has type 5 or 7 (all.c:331620-331625).
  - `token_past_rows(state, row) -> RowToken` returns the token word of `values[row]` for a restored cursor past a node's terminator, which stock reads from whatever follows the array (all.c:331537, 331546). In increment 2 it is a volatile read of `values + 8*row` through the record side table.
  - The engine is committed when it makes any call, so an answer or block that does not decode is a run-failing guard event in the adapter, not a fallback.
- `Tree` is generated from the decoded menu tables (E-MODAL-MENU-TABLES-150) by `//replacement/modal_runtime:menu-engine-tree`, pinned to the menu tables, image4 and strings identities. A node carries id, type, class or property, rows per page, `Wrap` (`+0x10`), `Availability` (`+0x14`), `Remember` (`+0x18`), parent, word 10, rows `{token, child}` and labels. Stock record addresses are not in the tree: the generator emits a separate `NodeRef` to record address table, carrying the tree's identity, that only the decode and mirror shim reads.
- The tree and engine types are unconditional modules of the bank crate; only the adapter, its seam assembly and its publication are behind `rb_menu_engine_owned`. `owned_menu::frame`, `owned_menu::lifecycle`, `recipe_ui` and `modal_runtime::picker` use the engine's `NodeId` and `RowToken` newtypes directly.
- Node `0x7a`'s `0xbf9a5c` writes property `0x285` with the remembered row's index; the engine performs it as `Effect::PropertyWrite` (increment 3).

## Placement in the guest

The adapter hooks the engine wrapper `0xbf95c8`, reached by all four stage consumers through `0xd4dd2c`, so stage events from stock and owned key actions both reach it.

- Seam: one published branch at `0xbf95c8`, built like the controller-75 seam (`replacement/modal_runtime/src/entry.S`, one RAM-push publication with rollback).
- On entry the adapter decodes the block and the last-move pair into the one in-progress `EngineState`, `ENGINE_STATE` in bank data. The block stays the source of truth while stock code also writes it (the bracket restore, `0x006364a4`, the initialisers, fallback kinds), so every event starts from what stock last left there. A nested entry while an event runs falls back to stock.
- Coverage is by event class, not kind: a class is (kind, argument class, node flags, node-specific branches). Node flags are `Wrap`, `Availability` and `Remember`; node-specific branches are the parent-id comparison in `0xbf9a5c`, the `0x285` write for node `0x7a`, the `0xbfad04` case for node `0x38` with class `0x228` (which writes `0x009573e4 = 0x9e`) and a node of type 5 or 7. For example: kind 4 with a row step on a node with all flags 0 and no node-specific branch. `apply` returns `NotOwned` for every class without an oracle case, before any service call, and the adapter then runs the stock kind switch and the stock snapshot store, exactly as `0xbf95c8` did.
- `apply` runs on that one state in place, through the `StaticState` handle on the bank-data `ENGINE_STATE`. Before each service call and after `apply` returns, the adapter writes each block word and last-move word whose mirrored value differs from memory, then returns the result to `0xd4dd2c`. Effects are performed during `apply`, through `perform`.
- Retirement: nothing is retired while any fallback class or any service reaches a stock engine function, and every function under `0xbfa234` is reachable from some fallback class today; `kind_switch` and `seek` also reach `0xbfa234`, `0xbfad04` and everything under them. `0xbf9a2c` is a retained interface (the redraw calls it). Instead of a retired-fetch watch, the run's checker checks owned coverage directly: it derives each event's class from the traced event registers and the generated tree, independently of the adapter, and fails the run on any entry to `0xbfa234` from the adapter's fallback call for an owned class. The adapter's fallback call and the `kind_switch`/`seek` service calls into `0xbfa234` and `0xbfad04` are separate call sites with distinct return addresses, and the guard tells them apart by the traced lr. The retired set grows when a function's last fallback class and last service use go; a reference scan over image4 and image5 (pointer tables, instruction-built addresses) must then show no other caller.
- Stack: `0xd4dd2c` runs on task 1, whose stack is `0xc00` bytes. The one in-progress `EngineState` lives in bank data and the engine holds no copy of it in a frame. The build statically bounds the engine's and the owned modal dispatcher's stack against the headroom below `0xbf95c8`'s entry, less a margin for stock callees ([package workflow](../replacement/menus.md#guest-package-and-comparison)). The margin is an estimate. In the guest pairs, every stage entry's sp minus the bound stayed above the stack base, and task 1's lowest changed word was 1256 bytes above the lowest floor (E-MENU-ENGINE-GUEST-PAIRS-150); that measured mark is a lower bound on depth. Bank frames reached through `rb_modal_call`'s action targets and the `0xd526fc` and `0xbfa800` bank hooks are outside the static bound.
- Tree on the route: the installed package republishes the shooting root's values and labels with two appended rows, so the guest archive's tree is the decoded tables composed with the package's own generated arrays, and those rows' children, the package's nodes, are not owned push targets. `apply` and the checker refuse an event whose open node's tree rows differ from the block's total before any call.
- The archive is built without jump tables (`-C llvm-args=-min-jump-table-entries=4096`), which the allowlist check needs in order to follow the engine's branches. The flag applies to the whole bank crate, so in the owned role the modal75 dispatcher and all other bank Rust code are compiled differently from the stock role's bank.

## Verification

- Host decode and mirror round trip: decoding each case's before and after blocks and the block at each of its service calls, and mirroring it back, gives the same 0x430 bytes.
- Host oracle per event class: the receipt's before block and event go through `apply` with services answered from the receipt. The engine must make the receipt's stock calls (notify, availability, initial row, snapshot store) in instruction order with the same arguments, with its in-progress block equal at each call to the receipt's block replayed to that instruction, and must give the recorded after block byte for byte, the recorded writes to `0x01467580`/`0x01467584`, every recorded snapshot word write in order (the receipts' watch over `[0x0093eb74,0x00944540)`) and the recorded result. The extractor (`//replacement/modal_runtime:menu-engine-cases`) pins the firmware and config identities and refuses rejected receipts, whose window ends after the rollback restore.
- Negative controls: deliberately wrong engines must each fail at least one case: no wrap, the skip rule inverted, no initial-row selection, no last-move pair, zero scroll, no push-saved classifier, kind 4's off-page scroll keeping the top, and the open rule's off-page scroll left at 0.
- Guest pairs: existing picker trajectories and the `--menu-observe` paths run once per role, stock against the owned-engine build, under the modal lifetime guard. Owner-approved equivalent engine acceptance substitutes picker 15 plus picker 250 for the known IMAGE SIZE/observe-1 hang; that screen remains unqualified. Each segment reads the block, the last-move pair and the three snapshot areas; event posts are counted with a trace site on `0x0063270c` (r0 = `0x1d`). Comparison: those reads equal, the `0x1d` post sequence equal, `modal-settings-compare` equal (it already covers the `0x285` write and the settings copies), render-compare content equal, and no fallback entry for an owned class.
