## 3. Draw class and the owned set

The owned code is the loop and layout logic of the two functions: which rows, in which order, at which positions, on which page, with which selection and scroll state, and the report. Every per-row dependency stock calls stays a stock call made by the owned loop at the same point with the same arguments: the three hooks, `FUN_0116cf50`, `FUN_01163e04`, the menu-table accessors and the draw leaves. A row a hook draws is therefore drawn by stock code in both roles, and no static classification of hook rows is needed.

`DrawClass` is decided at the function entry, from the arguments and the menu block:

- `DrawFunction`: `Tree` or `Picker`.
- `CallSite`: closed enum of the ten return addresses (lr at entry).
- `SnapshotSource`: `Live`, `SavedSlot1` or `SavedSlot2` (tree), `Live` or `SavedSlot2` (picker), from arg9 by the masks above; `Skipped` for picker modes 2 and 3.
- `ListKind` (tree only): `Flat` or `Tree`, snapshot word 0 after the node `0x25`/`0x38` override.
- `NodeId`: the record id of r0 in the composed menu tree's record-id space (the engine design notes record ids and registry indices differ for some nodes; `1167a00` passes record ids).

R1 owns `Tree` from `CallSite::MenuList` (`1167a5c`) with `SnapshotSource::Live` and `ListKind::Flat`; `Picker` from `CallSite::ValuePicker` (`1168ce0`) and from `CallSite::FnPicker` (`116c584`, report at the picker entry's SP+76), each with `SnapshotSource::Live`; and the node-1 pane `FUN_011662a0` from lr `0x01158184` for the depth, kind and mode combinations its native cases cover (contract [root-pane.md](display-render-contracts/root-pane.md)). All three exclude package nodes (`RowChild::Package`), and every other class falls back to the stock function before any draw. The checker derives the same class from the recorded entry registers, stack arguments and menu block, and the composed tree, independently of the adapter.

## 4. Owned code

- `replacement/render_commands` (`no_std`): the target design's section 2.1 types, `StockObject` (observed object bytes decoded into resource id, text reference, position, bank and state, with unconfirmed fields kept as an explicit byte array), and `decode_draw_state` from banks and lists into a `DrawList` per bank in list order. `TextRef::Catalog` takes the bound of the installed label table (`0x849` with the bank, `0x83d` without), passed in at decode.
- `replacement/menu_widgets` (`no_std`): `tree_list` and `value_picker` run the loop over `(Tree, NodeId, Snapshot, DrawArgs)` and call `DrawServices` at every point stock calls a dependency, in stock's order, including every draw leaf: a default row's leaf calls are issued inline at the stock point, interleaved with the hook calls exactly as stock interleaves them, and the `DrawList` is the typed record of those calls, not a later pass. They produce the report (`DrawReport`, 0x44 bytes) and the side-state writes (`SideState`: `0x15e64d8+0`, `+8`). `DrawServices` covers the hooks, `FUN_0116cf50`, `FUN_01163e04`, the menu-table accessors (`menu_tree_summarize_node`, `menu_tree_describe_child`, `0xbf9360`, `0xbf93e0`, `0xbf8f4c`, `0xbf90f0` and the others the step-1 sites find), the setting reads and the draw leaves.
- Adapter (`replacement/render_adapter`, `cfg(rb_render_owned)`): `rb_render_picker_apply` and `rb_render_tree_apply` decide the class from the entry registers, stack mode, LR and menu block. The current record pointer and record id must match the composed engine tree; package children and unknown records refuse. Tree classification uses the retained read-only `0x61ca2c` kind getter and the node-0x25/0x38 overrides. The widgets call stock through named A32 `blx` trampolines at their qualified service boundaries, write the report and side state and restore the panel font. The picker uses the installed label bound `0x849`.
- Seams (`replacement/render_adapter/entry.S`): entry-word branches at `0x1164e1c` and `0x1163f2c` land at `rb_render_tree_entry` and `rb_render_picker_entry`. Each saves r0-r12 and LR, passes the original stack and report pointer, calls Rust and restores the registers. Fallback recreates `push {r4-r11,lr}` and resumes at `+4`; the shared busy flag refuses nested entries.

### Prerequisite 2: UILIB stack admission

Source inspection at x70view `a72c95a3572562fc05f359b4f35915f3a0243b19` (`xm1-decomp show 0x110f960`, `0x725c6c`, `0x110871c`), confirmed against `decode/img6.dis`, `lz/id4.dis` and `decode/loader-40000.dis`. The constructor is exact; the allocator and draw dispatcher C are NONMATCHING reading aids.

- Creation: the plain hook calls `overlay_initialize_task` at `0x110f9e0`. The initializer creates channel 33 (`0x110f97c-0x110f984`), then submits task id 33, name `"uilib"` at `0x110f9f0`, priority 9, stack size `0x1000`, entry `0x1109130`, argument zero (`0x110f990-0x110f9cc`, specifically `e3a03a01` at `0x110f9ac`).
- Allocation is a bump allocation from the statically reserved task-stack arena, not the general-purpose heap or an inline static 4 KiB array for UILIB. `dispatch_create_task` stores the requested size and asks `0x725c6c` for the base (`0x725e40-0x725e74`). That allocator reuses the task's inactive cached allocation when present (`0x725cd4-0x725d38`); otherwise it reads the cursor at `0x4089ea98`, bounds the request against the `0x4b000`-byte arena beginning `0x40a10200`, removes alias bit `0x40000000` for the output, advances the cursor and caches base/size/active (`0x725d3c-0x725da0`, arena literal at `0x725dd4`). Creation order determines the base; do not hardcode task 1's base.
- Runtime descriptor: a task node's word `+8` points to the 40-byte creation record; its words `+0x10` and `+0x14` are stack size and base. The kernel reads exactly these fields and publishes initial SP = base + size to node `+0x18` (`0x43f78-0x43f88`, loader listing). Native task nodes have 56-byte stride (`0x43fe0-0x43fec`). At a seam, the current-task cell is `0x40054760` on primary or `0x400e4720` on secondary. Task 33's node is `0x4006060c` or `0x400f05cc` respectively; follow its `+8` pointer rather than assuming the creation-record placement. The record must identify entry `0x1109130`, kernel priority 8, stack size `0x1000`, task id 33 (`+8`, `+0xc`, `+0x10`, `+0x20`).

The stock tree's 352-byte and picker's 344-byte frames belong below those entries, not in the caller sums.

`host/firmware/RenderStack.hs` exports `checkRenderStack :: ArmElf.Elf -> (Word32 -> Bool) -> Either String RenderStackReport`. Pass the linked `kernel.elf` and the entire owned-runtime address predicate, not merely the two adapter ranges. It reuses `EngineStack.stackDepth` from `rb_render_tree_entry` and `rb_render_picker_entry`, including reachable owned callees and tail branches, and refuses unresolved branches, recursion and unaccounted SP writes. Each entry must satisfy `depth + 1024 <= headroom`, using the engine's stock-callee margin. The owned allowances are 2392 and 2696 bytes respectively. The margin is the engine's policy, not a new proof of retained draw-leaf stack demand.

The pane increment checks `rb_render_pane_entry` separately. Its node-1 caller chain retains the task/dispatch frames above (64 bytes), the 32-byte handler `0x01123f2c` through its BL at `0x011240f4`, the bank's published `rb_bank_draw_root`, and the stock wrapper's continuation `0x01158160` through BL `0x01158180`. `RenderStack` computes an ELF-derived maximum from `rb_bank_draw_root`, including its owned callees and the 16-byte stock-root trampoline, and subtracts that prefix plus 96 stock caller bytes from 4096. It then requires pane-owned depth plus the 1024-byte retained-stock margin within that headroom. The root wrapper's 16-byte frame is already in the prefix. This conservatively includes bank branches that do not reach the owned pane.

The earlier stock/owned picker observations reached changed-word address `0x00a4d454` against base `0x00a4ce00`, approximately 2476 bytes below the stack top. That is a lower bound on stack demand, not a static bound or pane-entry-specific minimum-SP qualification. The cutover must separately measure introduced pane invocations against the revised allocation criterion below.

**Revised finite-emulator cutover stack criterion:** capture the current-task cell, node `+8` and all ten creation-record words at the seams and segment boundaries. Validate Task 33's actual allocation `[0x00a4ce00,0x00a4de00)` and the existing 64-byte bottom guard, with continuous descriptor/backlink and attempted-write protection over the declared installed lifetime. Every introduced adapter invocation, including classification, fallback prefixes, nested invocations, retained callees and attributed preemption, must have complete source/context coverage, an architectural minimum SP at or above `descriptor.base + guard_bytes`, and a restored return or recreated fallback frame. Reject missing, ambiguous, refused or unfinished evidence. Keep the emitted owned-frame and conservative caller-headroom admission unchanged. Its imported 1,024-byte retained-stock estimate is informational at runtime, not a transitive retained-callee bound. Keep the whole-stack baseline/end changed-word mark as a separate lower-bound observation; do not compare it with an invocation's estimated floor. No fill pattern or writable instrumentation is introduced.

This explicitly revises the former rejection below `entry SP - (ownedDepth + 1024)`; it does not declare that criterion passed. The source-bound classifier staging receipts preserve 15 failed owned intervals under the old criterion: pane demand reaches 1,812 bytes against 1,476 and tree demand 1,740 against 1,580. The 1,024 bytes originated as a Task 1 estimate from a sampled 248-byte stock demand (`EngineStack.hs:30-37`), not Task 33's 4,096-byte allocation. The revised consumer must report a separately named allocation-based verdict and retain those estimate violations visibly.

The claim is limited to the exercised emulator routes. Neither active-invocation minima nor the separate lifetime bottom guard establish whole-task overflow freedom, a static transitive native-callee bound, future-path bounds, all-interleaving safety or absence of early SVC IRQ work. Raw CPSR, depth, owner and minimum coordinates remain evidence without filtering those samples.


## 6. Qualification

Under [spec/11's review and rerun rules](../spec/11-incremental-firmware-replacement.md#review-and-reruns) R1 qualifies on the host; the guest comparison is the display/render subsystem's one cutover pair.

1. **Contract, from the decomp and bytes.** For each function: arguments, the snapshot source per mode, the ordered list of `DrawServices` calls with their arguments as functions of the inputs (the `bl` sites in `0x1163f2c..0x1165aa0`, read in bytes, NONMATCHING C as reading aid), the out-structs each callee fills, the report fields, the side-state writes and the panel-font save and restore. An instruction after a `bl` that is also a branch target reached without the call (`11653d0 bne 0x11653dc` skips the leaf at `11653d8`) is part of the control flow the contract states.
2. **Host cases (native-case runner).** Each case maps the image slices the function and the menu tables need, a menu block `0x9571d0`, `0x15e64d8`, the panel font and the palette block, and calls the function with the class's arguments. Every `DrawServices` callee is a declared stub whose return value and out-struct bytes the case supplies; the stub events are the service-call sequence. Expected events and final memory (report, side state, panel font restored) are derived from the contract before the run. Cases cover each owned class: rows fewer than, equal to and more than a page, each page, scroll top 0 and nonzero, cursor on first, middle and last row, rows offered, disabled, hidden and variant, hooks returning 0 and 1, `FUN_0116cf50` zero and nonzero, and the picker's setting `0x44` values and label-id bound.
3. **Stock and candidate on the same cases.** The stock function and the owned loop (built for the same entry ABI and placed at an executable address in the case) run every case; both must produce the expected events and memory. Negative controls (selected row unstyled, page tabs off by one, scroll top ignored, a hidden row drawn, a disabled row styled as offered, report `+0x3e` wrong, `0x15e64d8+8` wrong) each fail at least one case.
4. **Compose.** Completed host-only in `private-data/analysis/x-m1-1.50/ram-push/RenderAdapter/r6/`: modal75 + menu-engine + render archive, 227 publications, both render hooks replacing old word `0xe92d4ff0`, zero allowlist violations and admitted task-33 stack bounds. All nine composition host test targets pass, including production-class decisions on 118 recorded native model inputs and 41 refusal/boundary inputs. Artifact hashes, exact commands and service-boundary details are in [the adapter README](../replacement/render_adapter/README.md). This does not establish the cutover pair.
5. **Cutover pair** (one per display/render cutover, on ControllerStrategy's `pair-runs-4` set when it exists): owned engine plus owned draws against stock, with the draw-state reads (entry: stack arguments, menu block, `0x15e64d8`, list heads; return sites `0x1167a60` and `0x1168ce4`: report, `0x15e64d8`, palette block, list heads, requested draw events, a declared bank set whose unread banks' heads and tails must be unchanged), a residency check (an owned-class draw reaching `0x1164e20` or `0x1163f30` while resident fails; an owned-class draw without an adapter-entry hit fails), the task-33 stack bound and high-water mark, raw byte equality of the draw state per paired draw except the clock exemption and the source-bound allocation handles below, and render-compare under its normalizations. A difference is localized by staging engine-only owned execution before owned render execution.

The `0xd4`-byte resource object's word `+4` is a constructor-return allocation handle. Image-6 bytes `0x0117d75c..0x0117d760` call `0x006dce28` and store r0 at `[r4,#4]`; `0x0117d800..0x0117d804` do the same for `0x006dcc08`. Every qualification observation requires continuous provenance from the first observation, including zero-event intervals. Uninstrumented receipts establish localization evidence, not render qualification, even when their raw draw bytes are equal.
