# File and media service: interface inventory draft

## Evidence and decision boundary

This is the host-only research inventory for the storage/file service of [the subsystem map](subsystem-replacement-map.md#f-storagefile-service-a-promising-interface-with-unresolved-backend-laws), built on the X-M1 1.50 image4 listing in the same form as [the RTOS manifest](rtos-platform-manifest-draft.md). It qualifies nothing and runs no guest code. Every contract below is read from `private-data/analysis/x-m1-1.50/lz/id4.dis` and the pinned image4 bytes; inferred names carry [INFERENCE]. Proposed boundaries are **[INFERENCE]**.

The machine-readable artifact is `private-data/scratch/FileManifest/manifest.json` (E-FILE-SERVICE-MANIFEST-150), generated by `replacement/media_permit/FileManifestMain.hs` (target `//replacement/media_permit:file-manifest`) from the reviewed contract input `replacement/media_permit/file_service_contracts.json` and validated against `schemas/file-manifest.schema.json`. It holds 230 entry contracts and 32 shared objects. Each entry carries its family, recovery level, arguments, result, status codes, context, touched objects, callers, a grounded list with listing citations, an unknown list, and the generator's extent and census.

## Method

The generator parses the media request table at `0x814740` (34 {code, handler} pairs ending in a zero pair at `0x814850`) and refuses a contract input that omits a handler or gives one the wrong code. It derives every entry's extent through the reviewed `StockInventory.deriveFunction` with no external tails, over the window from the entry to the next image4 BL target, listed entry or handler. A refusal claims no end. The census is a linear decode of every image4 word: BL sites, B sites outside the entry, aligned literal words and MOVW/MOVT pairs equal to the entry address, MOVW, MOV-immediate or PC-relative LDR loads of `0x2cXX` values not completed by a MOVT, and constructed addresses inside each object. Census sites are candidates: embedded data decodes as instructions, and Thumb, register-indirect and other-image callers are not seen. The generator had independent source review in two rounds, which removed MOVW/MOVT address halves from the message census (all 23 `0x2c34` sites and 13 of 15 `0x2c04` sites were halves of `0x812c34` and `0x942c04`). The contracts were written by six research passes and then independently reviewed against the listing in three scopes, with one correction round and one verification round.

## Request path

A client request crosses two tasks. Posters build a 12-byte header `{u16 code +0, u8 source task +2, u8 destination +3, u32 payload length +4, u32 payload pointer +8}` and send it through `0x71fde4` to message id `0x65`, the mediamsg task (entry `0x721744`, priority 2, stack `0xc00`, created by `0x721834`). `0x72503c` copies the payload before queueing, so a poster's stack payload need not outlive the send. mediamsg routes each request through the 52-arm jump table of `0x721578` (indexed by code minus `0x2c01`), serializes opens against open handles of the other class, and forwards through `0x7211d4` to id `0x1c`, the media task (entry `0x71fe7c`, priority 10, stack `0xc00`, created by `0x71fd40`). The media task receives with no timeout, takes a fast path for `0x2c17`, otherwise searches the table linearly, calls the handler with r0 = header and ignores its return. An unknown code gets no handler, reply or callback.

Codes `0x2c2d..0x2c34` are alternate codes, not synchronous ones: each base poster selects one from a variant word independent of its synchronous flag, and every synchronous wrapper passes variant 0. `0x7211d4` translates them before forwarding (`2c2d->2c17`, `2c2e->2c18`, `2c2f->2c19`, `2c30->2c1a`, `2c31->2c1c`, `2c32->2c1e`, `2c33->2c08`, `2c34->2c13`), so the media task never sees them. In mediamsg an alternate-code open sets session class 1 and a primary-code open class 2; requests of the blocked class wait in a 48-slot deferred queue at `0x9102e0` and replay when the last handle of the open class is released. Opens are intercepted: mediamsg replaces the payload callback with `0x7217f0`, sleeps, and on wake records the handle in the 20-word open set at `0x910290`. Two failure modes are in the bytes: a full open set makes `0x72129c` branch to itself at `0x7213a0`, and a full deferred queue drops the request with return 0 and no callback, so a synchronous client then waits on semaphore `0x3b` with no timeout.

Asynchronous wrappers return the tag (open) or 0 and deliver `callback(status, value)`. Blocking wrappers pass a nonzero synchronous flag: the base refuses tasks `0x1c` and 0 with status 9, takes semaphore `0x3a` (`0x71bc2c`, owner recorded in `0x910134`), posts, waits on `0x3b` (`0x71bc90`, both with timeout `0xffffffff`) and reads the result pair at `0x910138` (+0 status, +4 handle or count). No poster except `0x71c504` tests the post result, so a blocking call whose post fails still waits; `0x71c504` returns 9 on a failed blocking post without releasing `0x3a`. Before posting, open, read, write and close test card state `0x71ddf0(0)` and deliver 1, 2 or 5 on refusal; open also delivers 8 when `path[1] == ':'` and `path[0]` is not a letter, and 5 when the letter's registry index (`0x70ec84`, -1 when unregistered) differs from the active context's `+0x114`. When the local-mode word `0x8fc8a4` is 1, open accepts only paths with the 21-byte prefix `A:\DCIM\100_FUJI\DSCF` and completes in the caller with handle 1, and seek and close complete without posting.

The other 32 caller-facing and blocking wrappers post `0x2c06..0x2c25` and the alternate codes; they are listed in the manifest with their payload layouts. Only `0x71c648`, `0x71c670`, `0x71c720`, `0x71c7bc`, `0x71c7e0` and `0x71ce84` have direct image4 callers. [The file report](named-recipe-reach.md#62-the-stock-file-task-abi-byte-read-unless-noted) places the WT_LOG exporter and auto-act loader callers in image5, which this census does not read.

## Handle manager

A handle is a tag, not a slot. `0x71ef18` waits on semaphore `0x3c`, takes the sequence word `0x910200` plus one (a negative candidate becomes 1), skips any candidate already in one of the 16 slots at `0x9101c0`, stores the sequence before looking for a free slot, and writes the tag to the first zero slot; with no zero slot it returns 0 but has already advanced the sequence. `0x71eff4` clears the slot and releases `0x3c` even when its own wait failed. A separate 16-pair map at `0x910140` binds tags to file indexes: `0x71ea34` claims an index through `0x71e960` and records `{index, tag}`, returning the index without recording a pair when all 16 pairs are in use; `0x71eb28` translates a tag, and `0x71eaac` unbinds it. Open allocates the tag in the caller's task (`0x71c468`) and binds it in the worker (`0x71f2a8`); a failed open releases the tag, unbinds it and sets the handle to 0 (`0x71f3cc..0x71f3e8`). The null-volume branch of open `0x7115a4` delivers 5 without reaching `0x71f2a8`, so that tag is never released. Close (`0x71f1d4`) releases the tag, translates and unbinds it, then closes through `0x6ffff4` or `0x6ffdcc` and frees the index.

## Completion codes

Workers translate filesystem raw status through `0x71d450` (39-entry jump table at `0x71d464`; raw above 38 gives 5). The client codes are 0 (raw 0), 1 (raw 1), 3 (raw 14, 32), 4 (raw 18), 5 (raw 2, 5, 6, 9, 10, 11, 12, 15, 16, 23-31, 38 and above 38), 6 (raw 7, 8), 7 (raw 17), 8 (raw 3, 4, 19, 35, 36, 37), 9 (raw 20), 10 (raw 21), 11 (raw 22), 12 (raw 34), 13 (raw 33) and 14 (raw 13). Callers add 9 for a refused blocking call and 1, 2, 5, 8 from the pre-post checks. Some paths deliver raw values without translation: `0x2c10`, `0x2c11`, `0x2c12` and `0x2c2b` for some statuses, cancelled `0x2c03/0x2c04/0x2c0a/0x2c0c` (status 11 through context bytes `+0x1f6/+0x1f7`), the local-mode read redirect (0 or 5, and it never signals `0x3b`), and `0x2c00/0x2c01`, which do not load a status before calling back. `0x2c2a` translates its result twice, so a compare mismatch (8) reaches the caller as 6. The callback slot `0x91028c` is mediamsg state `0x910218+0x74`: `0x72129c` saves the client's open callback there and `0x7217f0` calls it with the open status and handle, then clears it.

## Volume registry and media state

The registry at `0x814730` is two 8-byte slots `{letter, valid, volume index, 0, class word}`; the stock data registers `'C'` as volume 0 (class 8) and `'B'` as volume 1 (class 7), and no store to it was found. `0x70ec84` maps a letter to its index and returns -1 for an unregistered letter; `0x70ec08` maps back. The active media-state record is the pointer `0x910204`, filled by the attach worker `0x71f7dc` (run by `0x2c00`), which clears `0x17474` bytes of the caller's record and sets `+0x114` to the volume index; the detach worker `0x71fa9c` (run by `0x2c01`) sets `+0x114` to -1 and clears the pointer. Card state `0x71ddf0` reads flag bits of `+0x16bd8`. Neither worker updates a media epoch counter. The manifest holds 13 volume-registry and 20 media-state entries, including the DCF path builder `0x70fbfc` and the 41-selector getter `0x7101e4`; their image5 callers are not read.

## Grounded and open

Grounded by this inventory: the two-task request path and its code translation; every request table row and its posters; the open/read/write/close wrappers, blocking forms and base posters with their payload layouts and pre-post refusals; the handle manager and tag map; the completion translation table; the registry layout and letter mapping; attach/detach effects on the active context. Open, and blocking a file-service replacement:

- The filesystem bodies below the workers (`0x7004b0`, `0x700768`, `0x7008a4`, `0x700b10`, `0x719de0`, `0x71a93c`, `0x704374`, `0x6ff4f0` and others) are not read, so 101 contracts stay partial and their status sets are lower bounds.
- 53 extents refuse; 23 request handlers have no derived end.
- Callers outside image4 (image5, plain image), Thumb and register-indirect calls are not censused; most wrappers have no image4 caller.
- Writable close and flush, media loss, card errors and physical storage laws stay as stated in [the subsystem map](subsystem-replacement-map.md#4-dependencies-and-unknowns-5); nothing here executes them.
- The semantics of kernel semaphores `0x3a/0x3b/0x3c`, sleep `0x7240c8` and wake `0x724144` are taken from [the RTOS manifest](rtos-platform-manifest-draft.md), not requalified.
