# X-M1 1.50 exception entry and exit (#156)

Ledger: `E-RTOS-EXCEPTION-ENTRY-EXIT-150`. Scope: the loader exception entries, the common dispatcher, acknowledge and end-of-interrupt ordering, the IRQ nesting lifetime and the scheduler handoff in both X-M1 1.50 loaders. The image4 abort installation, the retained diagnostic hooks, the shutdown poll, halt and the VFP owner stay stock.

## 1. Owned extents

Each loader's bytes were read from its own listing, not derived from the other.

| Block | A | B | bytes |
|---|---|---|---|
| vector bodies and IRQ entry/exit | `0x40100..0x40368` | `0xd0100..0xd0368` | 0x268 |
| fault record in retained-literal slack | `0x403a0..0x40410` | `0xd03a0..0xd0410` | 0x70 |
| common dispatcher | `0x40cac..0x40d50` | `0xd0cac..0xd0d50` | 0xa4 |
| ack/EOI wrappers and FIQ hook | `0x40d50..0x40d98` | `0xd0d50..0xd0d98` | 0x48 |
| Rust decision bodies | `0x430a8..0x432f8` | `0xd30a8..0xd32f8` | 0x250 |
| vector-slot setter (owned no-op) | `0x43810..0x43834` | `0xd3810..0xd3834` | 0x24 |

The vector bodies `0x40100..0x40368` and the CP14 identity `0x427b8..0x4286c` are byte-identical between loaders. The unhandled-vector marker is not: loader A initializes and compares `0x42840`, loader B `0xd2840` (`0xd290c..0xd2948`, `0xd30d4..0xd30dc`). The dispatcher differs in six words (`0x40cbc`, `0x40cc0`, `0x40cf8`, `0x40cfc`, `0x40d18`, `0x40d1c`), acknowledge and end-of-interrupt in thirteen words each (the handler-table, active-slot and unhandled-counter immediates), the dispatch tail in one word (`0x437bc`) and the first transfer's idle stack in one (`0x436f4`). A blanket "byte-identical bodies" reading is wrong for those blocks.

The loader install at `0x40020..0x40084` still writes the seven target cells `+0x24..+0x3c` in the order undefined, SVC, prefetch, data, reserved, IRQ, FIQ and never writes `+0x20`. The retained literal pool at `0x40370` (IRQ stack top `0x70002000`) and `0x40410..0x40428` (dispatcher `0x40cac`, FIQ hook `0x40d70`, counter, lock, wrappers, dispatch flag) is read by the carrier and is not patched.

## 2. Carrier and frames

`stage/carrier.S` keeps every banked and mode-changing operation. The IRQ entry runs in SVC mode on the task stack, saves `r0-r3/r12/lr/pc` and the interrupted `spsr` as the 8-word frame `{spsr, r0, r1, r2, r3, r12, lr, pc}`, and for the first entry moves to `0x70002000` and stores the frame pointer at `0x70001ffc`. Nested entries keep the frame on the task stack. The handler runs with I clear and F as the interrupted context had it; acknowledge and end-of-interrupt run with I set. The fault vectors save the 16-word frame `{r0..r12, lr, spsr, r12, lr}` on the current mode stack and tail-call the dispatcher at `0x40cac`. The return restores the full saved status with `msr SPSR_fsxc` and uses `ldm ...^`. The stock vector uses `msr SPSR_fc` (`e169f001`), which leaves the stale SVC SPSR A bit instead of the saved IRQ status A; FIQ and SVC already use `_fsxc`. The owned S2 IRQ tail uses `msr spsr_fsxc`; the exception stage applies a named 4-byte repair at A `0x437d4`/B `0xd37d4` (`e169f000` to `e16ff000`) so the staged candidate's retained scheduler return cannot reintroduce the stale A, with preimage, confinement and restoration at both addresses. The word lies inside the S2 `irq_resume` extent `0x437a4..0x437dc`/`0xd37a4..0xd37dc`, so the repair and the corrected S2 binary share one logical owner; it is not a separate carrier.

The deferred IRQ dispatch branches to the scheduler at `0x4375c`/`0xd375c`, not to the fault dispatcher at `0x40cac`. The image4 abort handlers at `0x61c73c` and `0x61c7f0` are installed by the image4 patch at vector slots `0x2c`/`0x30`; both tail-call `0x40cac` with kind 3 or 4 (literal `0x61c8c4 = 0x40cac`). The carrier keeps that entry ABI. The hook cells `0x4004f10c` (resume gate), `0x4004f110` (FIQ), `0x4004f114` (exception) and the 17-word record at `0x4004f118` are read and published unchanged; the dispatcher calls the exception hook as `hook(kind, frame->pc)` and the FIQ hook as `hook(frame->pc)`. The vector-slot setter `0x43810` is an owned `bx lr`: retained startup `0x4cea0`/`0xdce60` calls `0x4ccd0`/`0xdcc90`, which calls the setter with `(index=0, value=0)` and would otherwise zero the first fault-record instruction through the table at `0x40380`/`0xd0380`. The table cells have no other reader, so the no-op leaves the fault body intact without a new data region. The shutdown poll `0x40df8`, halt `0x410fc` and VFP owner `0x42420` remain stock.

## 3. Decisions

`src/lib.rs` holds the decisions over a `Machine`:

- `lock_acquire`: observe `0x400c0804`; a free word tries the exclusive pair with tag `0x11` (CP14 identity `0x4003`) or `0x12`, retrying the pair on a lost store; a word holding the own tag proceeds; a foreign tag re-observes.
- `acknowledge`: select `0xfffb3000` or `0xfffb4000` by identity, read `+0x200`; zero or the domain's marker (`0x42840` A, `0xd2840` B) increments `0x400544fc` and logs code 6 with the incremented count in `r1`; otherwise scan `+0x230..+0x23c` for the first nonzero group and its highest bit, set TPIDRURW bit 31, and store `{+0x1c0, line}` at `0x40054500 + 8*priority`. No pending bit is cleared.
- `end_of_interrupt`: re-derive the line from `+0x230`, clear its `+0x120` pending bit, clear TPIDRURW bit 31 only when the nesting counter is 1, clear the priority slot to `{0, -1}`, and write zero to `+0x200`.
- `exit`: compute `counter - 1`; release the lock only when it is zero; decrement; consume `0x400546d8` and report dispatch only at zero. The release precedes the decrement and the flag consumption.
- `record_fault`: publish the kind and 16 frame words, log `(kind, pc)`, and return the published hook for the carrier to call.

## 4. Host evidence

`//replacement/rtos_exception:exception-host-tests` passes 16 behavioral cases: outer acquire/acknowledge, nested own-tag re-entry, nested exit keeping the lock and flag, outer release-before-decrement-before-dispatch order, outer return, the premature-unmask counterexample (counter 1 at unmask leaves the lock held), acknowledge not clearing pending, unhandled code 6, end-of-interrupt re-deriving a changed line, TPIDRURW only at depth one, lost-try retry, secondary tag 18, fault record/log/hook, absent hooks, and the FIQ one-argument hook. `//replacement/rtos_exception:exception-artifact-tests` checks both linked images' entry symbols and first instructions against the stock extents.

### 5.1 Controlled nested IRQ lifetime

The opt-in `--nested` observer installs its input at each core's first admitted idle WFI. It saves that core's modeled controller registers, routes unused source 127 through the registered IRQ120 handler, gives source 127 priority zero and moves already enabled priority-zero sources to priority one. Delivery uses `Board.raise_irq`, not a counter or CPU-state write. Modeled controller register changes use `Board.device_input` and `Device::write`; host memory APIs cannot access those MMIO registers. The receipt declares this controlled input and records both controller restorations.

`private-data/scratch/NestedException/owned-5/idle-tasks.json` reaches `observed-menu` with a clean memory watch, no machine failure and both fixtures restored. Each core executes a nested entry/frame/acknowledge/exit/return and resumes its interrupted outer handler with the saved register, stack and full status context. The nesting counter follows 1, 2, 1, 0; the nested interval retains the outer IRQ lock tag and dispatch flag. Primary resumes at `0x402d0` with tag `0x11`; secondary resumes at `0xd02d0` with tag `0x12`. Both resume with CPSR `0x20000153`.

The lock proof consumes every observed CPU word store to `0xc0804`, checks each before/value link and matches sample readback. It refuses a release/reacquisition inside the nested interval. Outer completion requires that core's own tag-to-zero store after its pre-exit boundary and before its return, with counter and dispatch cleared. A later foreign acquisition can leave a nonzero terminal lock; requiring terminal zero had rejected the valid secondary release followed by primary tag `0x21` in `owned-4`.

The same observer and fixture refuse the pre-repair stage2 candidate at `nested return did not restore the saved status`, retained in `owned-6-old-status-control/idle-tasks.json`. The stock `SPSR_fc` write and the inherited owned word lose saved A=1 in this controlled case. The replacement uses `SPSR_fsxc`; the trigger and dependency remain recorded rather than recreating the defect. Stage3 also repairs the S2-owned scheduler return word.

This proves a controlled nested path in each core of the pinned emulator, not natural higher-priority delivery, physical interrupt arbitration, arbitrary nested depth, cross-core exclusive-monitor behavior, full-native qualification or the final composed subsystem comparison. The observer's built runtime is `/nix/store/d6jchrjzkffjy15hb9y4isp5kzrj1h7j-fujimod-xm1-0.1.0`; the SDK test target passes separately.


## 6. Limits

Physical arbitration, priority, active-bitmap and nesting semantics, the `+0x200` read/EOI relatch, WFI with I set, the exclusive monitor across cores, the vector-base alias and the counter-equals-one startup window remain unqualified. The native-case runner refuses SPSR, banked and mode-changing MSR forms, so it cannot qualify the carrier. FIQ and the abort stacks are uninitialized by the loaders. The owned decisions call the retained helpers at their stock addresses; aggregate composition may replace those bytes with the owned global-lock helpers under the unchanged ABI.
