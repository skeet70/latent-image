# Display and render service: interface inventory draft

## Evidence and decision boundary

This is the host-only research inventory for the display/render project of [the subsystem map](subsystem-replacement-map.md#g-displayrender-service-clean-actor-seams-but-not-yet-a-complete-renderer-contract), in the form of [the file-service manifest](file-service-manifest-draft.md). It qualifies nothing and runs no guest code. Contracts are read from the X-M1 1.50 image4 (`lz/id4.dis`), image5 (`lz/id5.dis`) and plain-image (`decode/img6.dis`) listings and the digest-pinned images; inferred names carry [INFERENCE]. Proposed boundaries are **[INFERENCE]**. Names the emulator gives to render-boundary cells (`emulation/fujimod-xm1/data/xm1-150.json`) are model names; the manifest records what firmware code writes and reads each.

The machine-readable artifact is `private-data/scratch/RenderManifest/manifest.json` (E-RENDER-SERVICE-MANIFEST-150), generated by `replacement/media_permit/RenderManifestMain.hs` (target `//replacement/media_permit:render-manifest`) from the reviewed contract input `replacement/media_permit/render_service_contracts.json` and validated against `schemas/render-manifest.schema.json`. It holds 860 entry contracts, 70 shared objects and 4 queues.

## Method

The generator shares `ServiceInventory.hs` with the file-service generator, which regenerates its cited manifest byte-identical after the change. It derives every entry's extent in its own image through the reviewed `StockInventory.deriveFunction`, over the window from the entry to the next BL target in any of the three images, listed entry or image end; a refusal claims no end. The census is a linear decode of all three images: BL and B sites, literal and MOVW/MOVT references to entries and objects, and the queue sends. A queue send is a BL site of the kernel send `0x72503c` whose r0 is set by an unconditional MOV immediate or MOVW within the six preceding straight-line words. Census sites are candidates; Thumb, register-indirect and register-copied queue ids are not seen. The contracts were written by five research passes plus two extension passes, independently reviewed against the listings in four scopes, corrected in two rounds and verified. The generator and the shared module had independent source review in two rounds.

**UILIB.** The step `0x11090a4` receives one queue-33 request into `0x15e46c4` with no timeout; a failed receive returns without dispatch. On success a nonzero packet token is copied to the consumer token `0x14e3338` before filtering. The filter `0x1109018` drops a request only when its token is nonzero and differs from the sender token `0x14e32bc`, its family is `0x4000`, and either flag bit 0 of its slot in the screen table `0x110f9f8` is clear or its code equals the sender command `0x14e32ba`. The dispatcher `0x1108a2c` splits the u16 code into family and index: `0x1000` loads settings and sets the initialized byte `0x15e470d`; `0x6000`, `0x2000`, `0x3000/0x3001`, `0x8000`, `0x9000`, `0xa000` and `0xb000` dispatch directly; every other family waits for the initialized byte, display suppression `0x15e4820` gates `0x4000`/`0x5000`, and those two families index the 0x176-record screen table and the 0x6c-record sub-request table `0x11105b0`. Completion is an event, not an acknowledgment cell: `0x1108350` maps a finished `0x4000`/`0x5000` code to event records (for example `0xa22`, `0xa25`, `0xa30`) posted through `0x72b680` to queue 1 or 7.

**Graphic task.** `0x6d2700` receives queue-40 packets into `0x8e2024`, relays `0x3804` to VGLIB as a `0x5902` render with its callback in slot 4, and runs `0x3800` (three layout step tables selected by a mode word) and `0x3805` through step tables spanning several messages; the completions come back as `0x3802`, `0x3803` and `0x3806` posted by callbacks.

**VGLIB.** `0x6d7540` receives queue-73 packets into `0x8e2098` and runs one step table per command within one receive: `0x5900` open, `0x5901` close, `0x5902` render frame. `0x5902` applies a pending output mode change, renders the 24-layer draw list into each active plane's back surface, programs the display layer, arms a frame-done hook, waits up to 100 ticks for flag `0xfefe` and then calls the six posted callbacks; on failure it returns -255 and the callbacks are never called. Clients use `0x6dc8d4` (open), `0x6dca18` (close) and `0x6dcb60(slot, callback)`, which returns -11 when VGLIB is not open and -30 for a slot above 6; a slot-6 callback is never called.

**Vector engine.** Registers at `0xfff78000` (register n at byte 2n). `0x892eb8` queues 104-byte jobs in a 900-slot ring and wakes task 72; `0x8929f4` attaches IRQ 79 handler `0x8924c0`, programs the unit by job type and waits; the handler reads status register `0x34`, stops units by status bit and wakes the task; callbacks run after the job, and an empty list posts `0x5701` so task 71 retries parked submissions.

## Render requests and their callers

Only three BL sites of `0x72503c` take a constant queue id that reaches these actors: `0xdb64ac` (queue 33, r0 copied from r5), `0x6d2224` (queue 40) and `0x6d7f7c` (queue 73); about 100 other sends take their id at run time and are not closed. Clients post through wrappers:

- Main UI path (image5): `0xd38d28` (194 calls in 118 functions) and `0x105e7ac` reach `0xdb68dc`, which maps a UI event to a render command and sends `0x4xxx` commands through `0xdb673c` (static staged header at `0x15e46e8`, token advanced) and `0x5xxx` commands through `0xdb6804` (inline payload, no token); both reach `0xdb6464`, which sends to queue 33 with outer code `0x3100` and retries on -18 or -62. A repeated code is not resent while the sender token differs from the consumer token.
- UILIB `0x8000` kick `0x112e380`: 2590 calls in 1678 functions across the three images.
- VGLIB render requests `0x6dcb60`: 2 image4, 2 image5 and 45 plain-image call sites, including the batch submitters `0x1177c9c` (plain) and `0x648998` (image4).
- Graphic layout `0x6d175c` (`0x3800`): two image5 and two plain callers; synchronous when no callback is given, polling with no timeout.

The emulator cells `ui_pending 0x9500f8` and `ui_busy 0x950110` are a UI mode pending cell and transition latch written by `0xd350c4`; no render-queue code reads or writes them.

## Planes, scanout and completion

Display state is one 0x2c10-byte record at `0x957aa0`; the emulator's batch_busy, batch_callback, commands_dirty and display_pending are its fields `+0x2bfc`, `+0x2c00`, `+0x2c08` and `+0x2c0c`, reached as base plus offset. `0x1177c9c` waits while batch_busy is set; with commands_dirty clear it calls the callback at once, otherwise it sets busy, stores the callback and submits VGLIB slot 3 with completion `0x1177760`, which clears busy, runs the transition hook and calls the stored callback. Draws on targets 0 and 1 set display_pending; `0x1177d54` turns it into `0x6cfd84(0)`, a slot-3 commit request. Graphics layer source, geometry, enable and format setters (`0x6c9cf4`, `0x6c9d44`, `0x6c9e7c`, `0x6c9f70`) write only the shadow image at `0x96b9bc`; the per-frame routine `0x6ca3e0`, registered through `0x6c7318` on interrupt source 9/10 or 11/12, copies the shadow to the scanout blocks at `0xfff6b000`/`0xfff6e000` and then calls and clears every queued completion callback. Blanking `0x6cb8b4` moves plane and rectangle enables into a backup and clears them in the shadow. The staged plane descriptor is `0x95a064` and the last applied copy `0x95a03c`.

## Row-availability probe

`0xd52684(property, row)` is a synchronous image5 function of `0x6038` bytes. It dispatches first over properties 5..0x260 through the 0x25c-word table `0xd52700` (99 non-default arms), then for property 5 over items 0..198 through `0xd53098` (114 non-default arms). It returns 0 offered, 2 disabled, 3 hidden, and 1, a property-5 variant of 2 inside frame node `0x7a`; unknown properties and items return 0. Its only store outside the stack is a conditional byte write to `0x95453b`. It has 176 direct BL sites, all in image5, 59 of them self-calls.

## Grounded and open

Grounded by this inventory: the four actors' construction, queues, receive loops and command tables; UILIB's packet, filter, families and completion events; the main UI submission path and coalescing rule; VGLIB's commands and frame completion; the graphic task's layout commands and relay; the engine job path and IRQ completion; the display record fields behind the emulator cells, the shadow-to-scanout commit and its callbacks; the probe's dispatch and result domain. Open, and blocking a renderer replacement:

- 472 UILIB table handlers are bound but not read; screen-change semantics live there.
- 180 partial contracts name unread callees, including the OpenVG/EGL library (`0x855xxx..0x89xxxx`) behind VGLIB.
- 97 extents refuse, including the probe and the scanout commit.
- Queue ids reaching r0 at run time, wrappers' indirect callers and callers outside the three images are not closed.
- Engine register meanings beyond the start writes, whether reading status `0x34` clears it, the display timing and formatter blocks' laws, and physical panel output are not established.
