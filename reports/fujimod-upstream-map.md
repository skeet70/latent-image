# FujiMod upstream capability map

## Scope and source revisions

This maps every row of [Retained capabilities still missing](emulator-runtime-decision.md#retained-capabilities-still-missing-from-the-supported-fujimod-path), not the completion status of concurrent downstream integration work. The contract is the [interactive X-M1 viewer and its controls](../emulation/README.md#interactive-x-m1-firmware-viewer), together with the named research routes. Neither an upstream API nor a matching menu ID establishes a passing downstream route.

Source inspection used a checkout fetched with `nix shell nixpkgs#git -c git clone https://github.com/justjake/FujiMod.git /tmp/fujimod-upstream-map-FujiModViewer`, plus a detached worktree at the pin. **Pin** means `ecdb6cb653ca0fa3372e4a4cf92c88bffa13ae29`; **main** means the fetched `origin/main`, `d112b636b6afb85379b7f8bc55c271748b400241`. Links below freeze those revisions. Statements about main do not predict subsequent upstream changes. Estimates are **[INFERENCE] engineering days**, including synthetic behavioral checks, not measured durations. Shared work must not be added twice.

This is a source audit, not an execution or performance comparison. Upstream tests cited below were read, not run. Combined downstream behaviors not demonstrated by the inspected code are marked unverified. Nothing was opened upstream, pushed, or run against a camera or USB device. Existing [licensing gates](../LICENSING.md#release-decisions) are unchanged; this audit is not a new grant assessment.

## 1. Browser viewer

**At the pin:** [`Engine`](https://github.com/justjake/FujiMod/blob/ecdb6cb653ca0fa3372e4a4cf92c88bffa13ae29/packages/emulator-ui/src/engine/api.ts#L30-L115) already specifies boot, RGB/RGBA/bitmap frames, press/release/rotate, snapshot export/load, checkpoint/restore, Undo/replay, error reports, card insertion/formatting and power cycling. [`LCDViewer`](https://github.com/justjake/FujiMod/blob/ecdb6cb653ca0fa3372e4a4cf92c88bffa13ae29/packages/emulator-ui/src/viewer/lcd.ts#L130-L165) draws guest framebuffer pixels. The session controller binds input, frames, fault reporting and rollback. These are reusable implementation, not a blank frontend to rebuild.

**At main:** the [Engine contract](https://github.com/justjake/FujiMod/blob/d112b636b6afb85379b7f8bc55c271748b400241/packages/emulator-ui/src/engine/api.ts#L30-L115) and LCD drawing are unchanged. The [controller](https://github.com/justjake/FujiMod/blob/d112b636b6afb85379b7f8bc55c271748b400241/packages/emulator-ui/src/session/controller.ts#L128-L173) still owns fault/Undo behavior; it also accepts physical-control descriptions for default layouts. The X-M1 panel exists at [pin](https://github.com/justjake/FujiMod/blob/ecdb6cb653ca0fa3372e4a4cf92c88bffa13ae29/apps/web/devices/xm1/panel.json) and [main](https://github.com/justjake/FujiMod/blob/d112b636b6afb85379b7f8bc55c271748b400241/apps/web/devices/xm1/panel.json). Its explicit controls cover power, playback, Q, Fn, directions/Menu, Disp, command push and the subcommand dial. That panel alone does not establish coverage of our complete key set and twelve mode positions.

The native connection is still a plan at both revisions. [`EMULATOR_UI.md` at pin](https://github.com/justjake/FujiMod/blob/ecdb6cb653ca0fa3372e4a4cf92c88bffa13ae29/apps/web/EMULATOR_UI.md#L138-L148) and [main](https://github.com/justjake/FujiMod/blob/d112b636b6afb85379b7f8bc55c271748b400241/apps/web/EMULATOR_UI.md#L110-L120) leave Order step 4, `RemoteEngine` plus a native process serving the UI, unfinished. The proposed transport is WebRTC with control/card data and an LCD video track. The actual main [factory](https://github.com/justjake/FujiMod/blob/d112b636b6afb85379b7f8bc55c271748b400241/apps/web/src/engine/index.ts) constructs `WasmEngine`. A search for `RemoteEngine` in apps, packages and crates found documentation only at both revisions. [`crates/remote`](https://github.com/justjake/FujiMod/blob/d112b636b6afb85379b7f8bc55c271748b400241/crates/remote/README.md#L1-L46) is a camera-control abstraction with BoardRemote/Ff80Remote, not this browser Engine transport.

Coverage and differences:

- **Display:** reuse the existing LCD renderer. Delivery from a native guest remains unverified because the planned native browser transport is not implemented in the inspected sources.
- **Keys/dial:** [`ControlSession` at pin](https://github.com/justjake/FujiMod/blob/ecdb6cb653ca0fa3372e4a4cf92c88bffa13ae29/packages/emulator-ui/src/ui/controls.tsx#L251-L299) and [main](https://github.com/justjake/FujiMod/blob/d112b636b6afb85379b7f8bc55c271748b400241/packages/emulator-ui/src/ui/controls.tsx#L234-L299) serialize pulses with a Promise chain and release held controls on focus loss. They do not implement our 32-pending-plus-active bound, visible overflow refusal, pending-only clear and cancellation semantics. Releasing a held pointer is not cancellation of queued pulses.
- **Firmware picker:** the [pin picker](https://github.com/justjake/FujiMod/blob/ecdb6cb653ca0fa3372e4a4cf92c88bffa13ae29/apps/web/src/home/controller.ts#L227-L281) and [main picker](https://github.com/justjake/FujiMod/blob/d112b636b6afb85379b7f8bc55c271748b400241/apps/web/src/home/controller.ts#L229-L283) reset the current session before checking size and catalog hash. They accept catalog/release identities with a 256 MiB limit, not our compatible-candidate validator and 64 MiB contract. Preservation of the active guest/frame/checkpoint and rejected private bytes is not supplied by that sequence. Validation and candidate preparation must precede replacement.
- **Checkpoints:** actual checkpoint/restore/Undo support exists. The [pin worker](https://github.com/justjake/FujiMod/blob/ecdb6cb653ca0fa3372e4a4cf92c88bffa13ae29/apps/web/src/engine/wasm-worker-runtime.ts#L237-L248) and [main worker](https://github.com/justjake/FujiMod/blob/d112b636b6afb85379b7f8bc55c271748b400241/apps/web/src/engine/wasm-worker-runtime.ts#L238-L249) refuse rewind operations with attached USB, since external host transactions are not rewound. That is useful eligibility enforcement, not permission to reuse a snapshot across changed firmware/source/model identity. Our exact checkpoint eligibility matrix and HTTP behavior remain unverified against this UI.
- **Diagnostics:** upstream provides reports, profiles, metrics and fault rollback. These overlap our display of stop reasons, but not all local probe commands described in section 7.
- **Media:** the native card APIs at [pin](https://github.com/justjake/FujiMod/blob/ecdb6cb653ca0fa3372e4a4cf92c88bffa13ae29/crates/emulator/src/session/card.rs#L46-L175) and [main](https://github.com/justjake/FujiMod/blob/d112b636b6afb85379b7f8bc55c271748b400241/crates/emulator-session/src/card.rs#L48-L176) already expose contacts including protection, state, data faults and retained card media. The browser Engine exposes insertion but no protection/fault operation; main's [card_insert binding](https://github.com/justjake/FujiMod/blob/d112b636b6afb85379b7f8bc55c271748b400241/bindings/javascript/emulator/src/commands.rs#L102-L109) sets `protected: false`. A media CRC/data fault is not automatically our fail-next-transfer/strict-stop contract. Bind and qualify the existing primitives rather than porting a second SD model.
- **Card-only restart:** the browser [power-cycle implementation at pin](https://github.com/justjake/FujiMod/blob/ecdb6cb653ca0fa3372e4a4cf92c88bffa13ae29/bindings/javascript/emulator/src/lifecycle.rs#L22-L52) and [main](https://github.com/justjake/FujiMod/blob/d112b636b6afb85379b7f8bc55c271748b400241/bindings/javascript/emulator/src/lifecycle.rs#L22-L52) captures durable media plus control positions. Main's [`Media`](https://github.com/justjake/FujiMod/blob/d112b636b6afb85379b7f8bc55c271748b400241/crates/emulator-session/src/durable.rs#L9-L51) includes NAND changes as well as cards, and restores both. Our card-only restart discards NAND/settings and armed fault state. It needs an explicit retention policy, not an alias for upstream `powerCycle`.

**Recommendation: contribute the missing part upstream.** Implement the planned native Engine/server boundary and extend the shared controller with bounded input/cancellation, transactional firmware replacement with a caller-supplied admission policy, complete card operations and explicit cold-reset retention. Add the missing X-M1 bindings. Rough size: **10-20 days [INFERENCE]**, dominated by the native transport and behavioral qualification, not repainting an LCD. Whether our existing HTTP routes remain a compatibility adapter or are deliberately retired is a downstream contract decision. Once equivalent behavior is accepted, delete the retained browser-only `start_setup_viewer.py`/`emulator/server.py`/`boot.html` path and avoid a parallel project-authored frontend. Do not delete the Haskell research/client harness on that basis.

## 2. Loader-published flash-candidate UI trajectories

**At the pin:** the [install workflow](https://github.com/justjake/FujiMod/blob/ecdb6cb653ca0fa3372e4a4cf92c88bffa13ae29/crates/workflows/src/install.rs#L73-L185) offers `OwnedUpload`: caller-owned allocation, stock pointer borrowing, upload, guarded restoration and readback verification. The [FJMODP01 interpreter](https://github.com/justjake/FujiMod/blob/ecdb6cb653ca0fa3372e4a4cf92c88bffa13ae29/apps/web/src/patch/patcher.ts#L122-L174) verifies source/program/output hashes and bounded copy/decompress/literal commands.

**At main:** [install](https://github.com/justjake/FujiMod/blob/d112b636b6afb85379b7f8bc55c271748b400241/crates/workflows/src/install.rs#L73-L185) and the [patch interpreter](https://github.com/justjake/FujiMod/blob/d112b636b6afb85379b7f8bc55c271748b400241/apps/web/src/patch/patcher.ts#L122-L174) are unchanged between the inspected revisions. Upstream's historical `mod-install` responsibilities are split between workflows and USB operations, not a missing facility to recreate. Catalog identities select known firmware facts; they do not define our candidate acceptance trajectories.

**Coverage:** a verified patch artifact or checked host upload does not establish that a modified DAT's loader publishes the expected bank, independently per segment, without a RAM upload. Neither inspected workflow supplies our icon/Q-tile publication observations or stored route baselines. No equivalent candidate-specific lifecycle was verified upstream. This is not a claim that the emulator cannot execute such a DAT.

**Recommendation: keep local.** Implement that lifecycle in our existing Haskell route harness and compare the two recorded trajectories, approximately **1-2 days [INFERENCE]** for the inventory's bounded integration. Keep candidate construction, publication assertions, observations and `verify-candidate` gating/baselines local. The generic patch interpreter may be useful for its own format, but replacing our candidate generator or trajectory language with FJMODP01 is not required by this row and would change the reviewed contract.

## 3. Controlled fixed-frame source and numerical/statistics fixture

**At the pin:** Rust already implements the analytic RGB bars/ramp/moving-square source, BT.601-limited packing and histogram in the Python [host-image binding](https://github.com/justjake/FujiMod/blob/ecdb6cb653ca0fa3372e4a4cf92c88bffa13ae29/bindings/python/host-image/src/scene.rs#L1-L19). Its [histogram entry](https://github.com/justjake/FujiMod/blob/ecdb6cb653ca0fa3372e4a4cf92c88bffa13ae29/bindings/python/host-image/src/scene.rs#L410-L435) takes an explicit frame; the same file implements parameterized analytic statistics with profile `declared-analytic-statistics-quadrature-v1`. This is not a source generator absent from the pin.

**At main:** the RGB/crop/YUV/histogram implementation is extracted to the pure [`fujimod-virtual-scene`](https://github.com/justjake/FujiMod/blob/d112b636b6afb85379b7f8bc55c271748b400241/crates/virtual-scene/src/lib.rs#L1-L29) crate. `Scene` already contains a frame number. The Rust [statistics binding](https://github.com/justjake/FujiMod/blob/d112b636b6afb85379b7f8bc55c271748b400241/bindings/python/host-image/src/scene.rs#L272-L303) retains the generic statistics profile. Main therefore offers a cleaner Rust-only source reuse boundary; it does not require porting Python algorithms.

**Coverage:** deterministic pure inputs are available. A caller choosing frame 7 is different from freezing the native camera pipeline's scene, including all image/statistics consumers, for the session lifetime. The named generic statistics profile is not evidence of equality with our `declared-xm1-150-analytic-statistics-quadrature-v1` fixture. Exact crop/grid/program/output correspondence and a native X-M1 session-wide fixed-source binding were not verified. Menu-ID parity remains insufficient to establish visual parity.

**Recommendation: contribute the missing part upstream.** Expose the remaining statistics computation independently of Python as needed, and add an explicit per-session scene selection/frozen-frame policy with checkpoint identity. Reuse the existing frame-valued source instead of adding another pattern generator or a process-global frame override. Rough size: **3-5 days [INFERENCE]** including an authored numerical fixture and native-session tests. Keep our X-M1 fixture parameters, independently expected values and acceptance baselines local. Remove duplicate pure source/math implementations only after those comparisons establish equality.

## 4. Strict UI-conversion profile

**At the pin:** [`RunExecutionMode::Strict`](https://github.com/justjake/FujiMod/blob/ecdb6cb653ca0fa3372e4a4cf92c88bffa13ae29/crates/catalog/src/configuration.rs#L1656-L1679) declares refusal of unsupported hardware/bus behavior. The [scaler](https://github.com/justjake/FujiMod/blob/ecdb6cb653ca0fa3372e4a4cf92c88bffa13ae29/crates/emulator-exr2-isp-output/src/scaler.rs#L16-L81) implements a bounded image operation with explicit geometry checks.

**At main:** the [configuration](https://github.com/justjake/FujiMod/blob/d112b636b6afb85379b7f8bc55c271748b400241/crates/catalog-configuration/src/lib.rs#L1161-L1184) moves to catalog-configuration and still has only `Strict`; the [scaler](https://github.com/justjake/FujiMod/blob/d112b636b6afb85379b7f8bc55c271748b400241/crates/emulator-exr2-isp-output/src/scaler.rs#L16-L81) remains a bounded bilinear raster model. Generic strict mode is not the choice between our X-M1 declared UI-conversion adapter and refusing that adapter's operations.

**Coverage:** upstream supplies the unsupported-operation mechanism and a separate scaler model, not proof that our declared CPU-fallback dialect matches that model. The row requires forwarding a local option and binding local checkpoint identity to it. It does not require a second upstream global strict/discovery switch.

**Recommendation: keep local.** Select or refuse the declared adapter at our run-document/adapter boundary and key snapshots on that selection, approximately **0.5-1 day [INFERENCE]** for the inventory's option/identity work. Keep the provenance label `declared-ui-cpu-fallback`; a future independently supported hardware dialect could be offered upstream separately. Do not delete strict refusal or silently substitute upstream's scaler because its register window overlaps.

## 5. Closed stock service rehearsal

**At the pin:** [`Session`](https://github.com/justjake/FujiMod/blob/ecdb6cb653ca0fa3372e4a4cf92c88bffa13ae29/crates/usb/src/ff80/session.rs#L39-L70) and the service command modules implement identification, configuration, memory, diagnostic query and close. [`verified_writes`](https://github.com/justjake/FujiMod/blob/ecdb6cb653ca0fa3372e4a4cf92c88bffa13ae29/crates/usb/src/operations/verified.rs#L11-L53) plans bounded write/readback pairs; [`BorrowedQueries`](https://github.com/justjake/FujiMod/blob/ecdb6cb653ca0fa3372e4a4cf92c88bffa13ae29/crates/usb/src/operations/borrowed.rs#L14-L117) checks callback/output state, appends diagnostic calls and restores the borrowed words once after the batch. Authorization and code/cache qualification remain caller policy.

**At main:** the [session opening boundary](https://github.com/justjake/FujiMod/blob/d112b636b6afb85379b7f8bc55c271748b400241/crates/usb/src/ff80/session.rs#L39-L70), [checked writes](https://github.com/justjake/FujiMod/blob/d112b636b6afb85379b7f8bc55c271748b400241/crates/usb/src/operations/verified.rs#L11-L53) and [borrowed callbacks](https://github.com/justjake/FujiMod/blob/d112b636b6afb85379b7f8bc55c271748b400241/crates/usb/src/operations/borrowed.rs#L14-L117) preserve those operations. Production [`Backend`](https://github.com/justjake/FujiMod/blob/d112b636b6afb85379b7f8bc55c271748b400241/crates/usb/src/connection.rs#L599-L606) supports physical USB and USB proxy. Replay/model peers exist, and main makes testing facilities unconditionally compiled; this is not a public production emulated-endpoint provider. `Session::open`, `Io` and `Backend` remain crate-private.

**Coverage:** these are host-side protocol implementations talking to a device, not the guest-side USB controller/endpoint bridge. The rehearsal must exercise the same Haskell client used by `//transport:camera`, with enumeration, identity/configuration, scratch readback, stock query and receipt assertions. Swapping that client for upstream Rust would test a different client even if an emulator transport were added. No equivalent Haskell journal/receipt contract was verified upstream.

**Recommendation: keep local.** Run the existing Haskell rehearsal against the FujiMod guest endpoint and remove its retained Python driver dependency after the same assertions pass, approximately **0.5-1.5 days [INFERENCE]**. A public endpoint-provider backend for upstream's Rust client is a separate potentially useful contribution, not a prerequisite for our Haskell rehearsal and not permission to replace it.

## 6. Bulk-read and AF-ring E2E launchers

**At the pin:** the [bulk workflow](https://github.com/justjake/FujiMod/blob/ecdb6cb653ca0fa3372e4a4cf92c88bffa13ae29/crates/workflows/src/bulk.rs#L1-L35) already uses stock diagnostic E1 bulk access and catalog-selected window facts. This is not a missing bulk-transport implementation.

**At main:** the [workflow](https://github.com/justjake/FujiMod/blob/d112b636b6afb85379b7f8bc55c271748b400241/crates/workflows/src/bulk.rs#L1-L35) remains, with bulk/camera/identity catalog responsibilities split into dedicated crates. The [checked install workflow](https://github.com/justjake/FujiMod/blob/d112b636b6afb85379b7f8bc55c271748b400241/crates/workflows/src/install.rs#L118-L185) can upload and verify caller-owned bytes. Its ownership rules are reusable reference material, not our mandatory-unload proof.

**Coverage:** the row requires launching our client/recorder against an emulated endpoint and comparing capture bytes, alias reads, decoders and unload effects. An upstream bulk reader talking to physical USB/proxy does not supply our AF-ring payload, decoder acceptance or teardown receipts. Neither does it establish physical lens/ordinary-AF accuracy. No equivalent AF-ring experiment was verified upstream.

**Recommendation: keep local.** Change the two Haskell launchers to drive their existing operations through the Rust endpoint bridge and preserve their byte/decode/unload checks, approximately **1-2 days [INFERENCE]** for the inventory's launch/coverage work. Delete direct `continue_rec_scanout.py` launches only after qualification; retain our payload/decoder and Haskell journal contracts.

## 7. Interactive probe/stop diagnostics

**At the pin:** the [CPU trait](https://github.com/justjake/FujiMod/blob/ecdb6cb653ca0fa3372e4a4cf92c88bffa13ae29/crates/emulator-cpu/src/lib.rs) exposes register/memory access, execution and hooks. Board [observation](https://github.com/justjake/FujiMod/blob/ecdb6cb653ca0fa3372e4a4cf92c88bffa13ae29/crates/emulator/src/board/observation.rs) includes bounded memory/transaction watches and instruction points, not just boot execution. Browser Engine reports/profile are also present.

**At main:** the [CPU trait](https://github.com/justjake/FujiMod/blob/d112b636b6afb85379b7f8bc55c271748b400241/crates/emulator-cpu/src/lib.rs#L622-L625) and [board observers](https://github.com/justjake/FujiMod/blob/d112b636b6afb85379b7f8bc55c271748b400241/crates/emulator/src/board/observation.rs#L214-L253) preserve those primitives. [Instruction points](https://github.com/justjake/FujiMod/blob/d112b636b6afb85379b7f8bc55c271748b400241/crates/emulator/src/board/observation.rs#L376-L387) stop through pre-effect interception. A bounded run or instruction observer is a mechanism for stepping, not proof that the retained console command has been wired.

**Coverage:** architecture/stack/task decoders, address labels, command bounds, local stop-reason presentation and the supported console/HTTP command set are downstream interfaces. No equivalent end-to-end X-M1 diagnostic command surface was verified upstream. Upstream's fault Undo/report workflow covers a different part of diagnostics and should be reused by the browser work in section 1.

**Recommendation: keep local.** Inventory actual diagnostic callers and bind their supported effects to the upstream primitives, retaining only the local command adapters and research-format decoders, approximately **2-4 days [INFERENCE]** for the inventory's bounded surface. Do not port CPU stepping, hooks or bounded watch storage into a second engine layer. Retire a retained command only after its remaining callers are explicitly addressed.

## 8. Python-free staging and fixture preparation

**At the pin:** [`fujimod-firmware`](https://github.com/justjake/FujiMod/blob/ecdb6cb653ca0fa3372e4a4cf92c88bffa13ae29/crates/firmware/src/lib.rs#L254-L315) already decodes supplied DAT mappings in Rust, with checked extents/hashes and method-4 decompression. Container parsing is not intrinsically Python work.

**At main:** the [decoder](https://github.com/justjake/FujiMod/blob/d112b636b6afb85379b7f8bc55c271748b400241/crates/firmware/src/lib.rs#L254-L315) is unchanged. The split [`emulator-preparation` infrastructure](https://github.com/justjake/FujiMod/blob/d112b636b6afb85379b7f8bc55c271748b400241/crates/emulator-preparation/src/persistent_inputs.rs) adds reusable persistent-input preparation; catalog-configuration/firmware and emulator-boot provide more focused native boundaries.

**Coverage:** upstream solves reusable parsing/preparation pieces, not our owner-supplied private input locations, Haskell DAT admission, Bazel staging/runfiles, synthetic fixture generation, provenance receipts or each retained tool's input assumptions. The supported FujiMod RAM-push staging path already copies the selected DAT/ROM without `xm1-upstream` or `firmware_registry.py unpack`. That fact does not migrate the remaining fixture callers. A catalog's stock hash policy must not silently reject the compatible modified candidates our validator admits.

**Recommendation: keep local.** Preserve the Python-free Haskell staging boundary, reuse the native decoder where the Rust bridge needs decoding, and migrate each remaining retained caller individually. Delete its unpack/reference-tree dependency only when that caller no longer uses it. No new upstream feature is required merely to stage our selected inputs. Remaining size is caller-dependent, not a justified new aggregate estimate; an exact complete inventory of all fixture-preparation callers was not established by this source audit.

## 9. Pre-execution CPU-profile admission on mutable code

**At the pin:** [`Cpu::stop_before_instruction`](https://github.com/justjake/FujiMod/blob/ecdb6cb653ca0fa3372e4a4cf92c88bffa13ae29/crates/emulator-cpu/src/lib.rs#L713-L717) explicitly permits interception inside an instruction observer before guest effects. This is implemented, not only a trait default: the [R-profile backend](https://github.com/justjake/FujiMod/blob/ecdb6cb653ca0fa3372e4a4cf92c88bffa13ae29/crates/emulator-cpu-unicorn/src/rprofile/core/backend.rs#L423-L437) validates a live instruction entry and stops it. [Observer dispatch](https://github.com/justjake/FujiMod/blob/ecdb6cb653ca0fa3372e4a4cf92c88bffa13ae29/crates/emulator-cpu-unicorn/src/rprofile/core.rs#L571-L609) precedes instruction handling and returns when the observer requests stop. Installing an instruction observer while paused [re-translates affected code](https://github.com/justjake/FujiMod/blob/ecdb6cb653ca0fa3372e4a4cf92c88bffa13ae29/crates/emulator-cpu-unicorn/src/rprofile/core/backend.rs#L471-L513).

**At main:** the [trait](https://github.com/justjake/FujiMod/blob/d112b636b6afb85379b7f8bc55c271748b400241/crates/emulator-cpu/src/lib.rs#L777-L781), [implementation](https://github.com/justjake/FujiMod/blob/d112b636b6afb85379b7f8bc55c271748b400241/crates/emulator-cpu-unicorn/src/rprofile/core/backend.rs#L424-L438) and [pre-effect dispatch](https://github.com/justjake/FujiMod/blob/d112b636b6afb85379b7f8bc55c271748b400241/crates/emulator-cpu-unicorn/src/rprofile/core.rs#L657-L701) remain. Main adds translation/coherence and loop optimizations, but this boundary is not a new main-only feature.

### What that boundary covers

- **Newly decoded code:** with a matching instruction observer installed before running, the [pin classifier](https://github.com/justjake/FujiMod/blob/ecdb6cb653ca0fa3372e4a4cf92c88bffa13ae29/crates/emulator-cpu-unicorn/src/rprofile/core.rs#L461-L478) selects `ObserveAndEndBlock` for observed A32 instructions. The callback runs on the first execution, not only a later visit or after the run window. Main's [classifier](https://github.com/justjake/FujiMod/blob/d112b636b6afb85379b7f8bc55c271748b400241/crates/emulator-cpu-unicorn/src/rprofile/core.rs#L482-L509) preserves that selection; instructions handled through `Replace` also use the instruction observer contract. This is per-instruction interception, not an automatic block-wide R4F validator.
- **Same-size rewritten code:** upstream tracks translated backing bytes, not an address/length decode verdict. Its [write tracking and alias/peer invalidation](https://github.com/justjake/FujiMod/blob/ecdb6cb653ca0fa3372e4a4cf92c88bffa13ae29/crates/emulator-cpu-unicorn/src/rprofile/memory.rs#L651-L830) respond to writes touching translated bytes regardless of replacement length. The same implementation is present at [main](https://github.com/justjake/FujiMod/blob/d112b636b6afb85379b7f8bc55c271748b400241/crates/emulator-cpu-unicorn/src/rprofile/memory.rs#L651-L830). After a coherent write and required synchronization/flush, the observer remains installed and runs before the first execution of the replacement. Decoding fresh bytes there avoids our stale address/length key. This conclusion follows from the inspected paths; the combined local R4F rewrite/interception behavior has not been executed here.
- **Write-path boundary:** CPU writes, guest stores and notified backing/DMA writes participate in the inspected coherence mechanism. It requires stopped processors or the owner-barrier protocol for relevant external writes. Arbitrary raw pointer mutation without write notification is not covered. Any private admission cache must include bytes or a correct mutation generation; upstream translation invalidation does not repair a separate stale local cache.
- **Effects boundary:** stopping prevents the rejected instruction's effects. It does not undo previously allowed instructions, the write that installed the new bytes, completed DMA/MMIO, or earlier instructions in the enclosing block/run. If our contract requires rejecting an entire program/block before any allowed prefix runs, it needs separate pre-admission of that whole scope. A block observer plus an after-window scan does not obtain that guarantee from `stop_before_instruction`.
- **Evidence limits:** the [pin interception regression](https://github.com/justjake/FujiMod/blob/ecdb6cb653ca0fa3372e4a4cf92c88bffa13ae29/crates/emulator-cpu-unicorn/src/rprofile/core/tests.rs#L229-L260) checks stop/PC/progress; the [alias/peer rewrite regression](https://github.com/justjake/FujiMod/blob/ecdb6cb653ca0fa3372e4a4cf92c88bffa13ae29/crates/emulator-cpu-unicorn/src/rprofile/core/tests.rs#L1270-L1313) checks same-size replacement is executed through existing and newly mapped aliases/peers. These are separate tests, not a pre-existing combined R4F/no-side-effects negative-control matrix. Tests were read, not run. Full A32/T32 refusal-policy equivalence, every local DMA mutation path and cross-core admission under the downstream scheduler remain unverified.

### Cost, not a free correctness switch

A full-range instruction observer dispatches on every executed instruction. At the pin, observed A32 instructions use `ObserveAndEndBlock`, increasing translation-block boundaries and callback traffic. [Loop acceleration declines intersecting instruction observers](https://github.com/justjake/FujiMod/blob/ecdb6cb653ca0fa3372e4a4cf92c88bffa13ae29/crates/emulator-cpu-unicorn/src/rprofile/core/loops.rs#L376-L385), also at [main](https://github.com/justjake/FujiMod/blob/d112b636b6afb85379b7f8bc55c271748b400241/crates/emulator-cpu-unicorn/src/rprofile/core/loops.rs#L559-L563). Installing a full-range observer flushes translations; a bounded observer can [re-translate only affected pages](https://github.com/justjake/FujiMod/blob/ecdb6cb653ca0fa3372e4a4cf92c88bffa13ae29/crates/emulator-cpu-unicorn/src/rprofile/core/backend.rs#L603-L628). Fresh byte reads/decoding add per-execution work. These structural costs are visible in code; **no slowdown factor or throughput measurement was established**. A range-limited policy reduces coverage as well as cost and must state that scope.

**Recommendation: keep local.** Use upstream's existing instruction observer/interception and coherent write APIs to implement our narrower R4F refusal policy, including its reviewed CP15 exceptions. Remove the post-window admission claim and stale address/length cache after qualification. Rough size remains **2-4 days [INFERENCE]** for the local guard rewrite and behavioral negative controls, with performance measurement separate. Do not file an issue asking for an already implemented pre-effect hook. A translation-time admission API might be an optimization contribution after measurement; an upstream correctness issue requires a reproducer demonstrating a remaining failure in the existing boundary. The private upstream-candidate inventory was corrected accordingly.

## Boundaries that do not move upstream with emulator reuse

The [verification/baseline policy](../emulation/VerifyCandidate.hs), our patch candidate trajectories, the reviewed [RAM-push chain](../transport/FujiAF/RamPush.hs) and the Haskell transport journal remain local. Upstream's checked writes, callback batches, patch hashes and catalog facts overlap mechanisms, not these acceptance decisions. No inspected upstream implementation replaces our exact authorization/publication/rollback receipts or journal semantics. Moving those checks merely to reuse an upstream client would narrow the test contract. This report recommends no such cutover and changes no stored baseline.
