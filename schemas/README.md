# Research schemas v1

JSON Schema draft 2020-12 definitions capture the manifest and ledger contracts. Relative references resolve within this directory. Every instance carries `schema_version: 1`; incompatible changes require a new version and explicit migration.

| Schema | Instance |
| --- | --- |
| `sources.schema.json` | `manifests/sources.json` |
| `camera.schema.json` | `manifests/camera.json` |
| `firmware.schema.json` | `manifests/firmware.json` |
| `memory-map.schema.json` | `manifests/memory-map.json` |
| `evidence.schema.json` | Each nonempty line of `docs/evidence.jsonl` |
| `benchmark-trial.schema.json` | Each future private trial record |
| `benchmark-protocol.schema.json` | `manifests/benchmark-protocol.json`, the E-01 offline pilot design |
| `read-plan.schema.json` | The window list `//transport:camera read-config` executes, generated by `//readplan:read-plan` |
| `native-case.schema.json` | Synthetic and admitted stock Cortex-R5F native cases, subject to the [X-M1 CPU-profile restriction](../docs/principles.md#scope-and-evidence) |
| `af-simulation.schema.json`, `af-observation-action.schema.json` | AF model inputs and observation/action records |
| `af-session-annotation.schema.json` | Each private AF-attempt annotation record from `//af-session:af-session` ([session kit](../reports/af-session-kit.md#11-annotation-workflow)) |
| `recipe-set.schema.json` | A future `manifests/recipe-set.json`, the host-authored RC1 named-recipe set ([design](../reports/recipe-design.md)) |

The native-case schema is narrower than the compiled adapter for byte sizes, artifacts and expected events; [the actual limits](../emulation/README.md#case-contract-and-execution-authority) describe this unresolved contract gap.

Camera, firmware and memory-map manifests are partial baseline records, not a current body inventory; see [their scope](../manifests/README.md). The benchmark protocol defines the offline pilot design with unresolved private settings; its schema accepts only `draft-offline`, with no camera authorization.

The read plan binds the channel to opcode `0x1a0002` function 2 with `mb` 1 and a per-window length of exactly 256, because the firmware applies no length check on that opcode and the cap is a host obligation ([the read scope proposal](../reports/h2-read-scope-proposal.md)). A window offset is six lowercase hex digits ending in `00`, so an unaligned offset and an offset whose last byte reaches `0x420000` or beyond fail the pattern. The oracle names a window index and a byte offset at most `0xfb`, which keeps the five product-string bytes inside their 256-byte window.

The window list holds 1 to 2048 entries, with `index` in the same range. `//transport:camera` refuses above 2032 windows, where the derived journal allowance of 65536 bytes plus 4096 per window reaches its 8 MiB ceiling; 2032 carries the 1309-window complete capture of the `0x42000` extent and the `0x400000` block. Strictly increasing offsets, `index` equal to the array position and an oracle index naming a listed window compare sibling array items, which draft 2020-12 cannot express. The compiled plan check refuses all three, so a plan between 2033 and 2048 windows passes the schema and stops the compiled check; the compiled check is authoritative wherever the two overlap.

Run `devenv shell -- bazel test //tests:research-contracts` for metaschema, manifest/evidence, and rejection checks. Validation uses a pinned upstream schema checker. Language and build policy belongs to [current principles](../docs/principles.md#implementation-and-build).

Schema validation checks shape, not camera permission. Native-case, payload, clock, and observation/action contracts are specified in [the runtime contract](../spec/08-artifact-and-runtime-contracts.md); native-case and AF consumers implement the schemas linked above. A schema does not establish target ABI, hardware behavior or gate acceptance.
