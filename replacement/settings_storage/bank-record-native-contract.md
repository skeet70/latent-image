# Bank and area3 native composition

`BankRecordNative.prepareJoinCases` takes canonical image4, loader A, qualified record function extents, admitted property image4 and artifact, then the combined bank/custom/record sparse binary and its symbols. It returns stock, owned and refresh-omission `CaseSpec` groups. `CustomOracleMain` adds the compiled append- and CRC-omission artifacts through the same case producer and owns runner invocation and receipt production. `StorageRun` compares every role to the same model expectations. Inputs must already pass their existing artifact admission checks.

`prepareControlJoinCases` takes an oracle-only control property image and `Native.PropertyMetadata` extracted from the opaque control artifact. Its function/default extents belong to that control image, not the normal candidate. It does not derive or admit that control image as a production artifact. It returns only the initialized-record property-1 setter witness; a close-appends control executes the actual append and must differ in the medium while returning normally.

The module imports `Native`, `Oracle`, `CustomNative`, `CustomAdmission`, property classification/artifact/model modules and the qualified `Replacement.RecordStore.{Arm,Cases,Harness,Hardware,Model}` modules. Add it to the composed oracle binary sources, not to a library that `Native` imports.

## Executed path

The qualified custom fixture opens the real record service and boots the custom lifecycle against a synthetic area3 medium containing parity-sealed sequence 7. The join driver supplies independently dirty live custom bytes after boot, clears only the bank event journal, executes the selected bank sequence or custom-range write request, and calls the real custom reader. Stock refresh at `0x6a86c4`, append at `0x6ac7d4`, prepare/check callbacks and the raw request path execute image instructions. Owned fixed veneers route into the combined artifact. No refresh or append echo replaces those functions.

Function retirement follows `CustomAdmission.retiredSettingsRegions`; fixed ABI entries retain their four-byte veneers. Raw NAND backends, including `0x6aad94`, remain callable. The interval from the first custom entry through the final record entry is not wholly retired.

The medium and request ABI are the existing record harness convention. The kind3 geometry remains two blocks at `0x58` and `0x59`, 52-byte records, 127 records per block and a `0x600` program request. The synthetic request implementation uses erase-to-FF and program-by-AND. These are declared fixture laws, not camera physics. Scheduler calls for the record semaphore do not enter the bank mirror journal; bank semaphore calls retain their existing modeled journal.

Owned record permissions come from `CustomNative.ownedRecordRegions`. Two cache blocks occupy `0x8a0080..0x8e0080`, with ages at `0x89fa60..0x89fa68`, two tags at `0x8e0080..0x8e0088` and a timestamp at `0x8e0088..0x8e008c`. The obsolete cache-tag words at `0x89f8f0..0x89f8f8` and saved destination at `0x917fa8..0x917fe4` are absent from owned permissions. Stock retains its original record RAM layout.

## Independent outcomes

The existing typed bank oracle predicts banks, previous image, backing, request return status and bank effects. The record model independently finds sequence 7, appends sequence 8 when a custom-range request changes the payload, seals it with the qualified hardware model, predicts the entire two-block medium and encodes the persistence journal with the qualified record decoder convention. The returned custom record, previous and working lifecycle records, caller-visible read status and preserved registers are compared separately.

The record model starts with the same FF staging initialization as the executed record-service open. A program interrupted before persistence retains the independent bank journal prefix preceding custom refresh, including the mirror writes already completed by the bank operation.

The failed-program fixture retains the attempted `0x600` request but leaves the medium and previous record unchanged. The custom lifecycle keeps the changed working payload and reloads sequence 7. Stock ignores the raw program error and the enclosing request returns success. The before-program interruption uses the record harness memory guard before journaling or landing the request; its expectations include the imported backing, unchanged medium, pending lifecycle records and unreleased bank request boundary. The next-program-not-reached fixture selects persistence step 1 while this operation issues only step 0; it returns normally and preserves the landed sequence-8 record.

Ordinary application, initialize, restore and exchange witnesses start with dirty custom live bytes but must retain the record medium. Thus `application-appends-bank-as-area3` is detected by a real unexpected append and changed medium, not by observing an internal helper call. Existing 37 bank fault artifacts remain routed by the owning matrix; the application fault must additionally execute this joined group using its defective combined artifact.

Three semantic controls omit refresh, append or CRC preparation in the executed owned path. Refresh omission patches its executed fixed boundary. The compiled `record-append-omitted` variant returns the typed append refusal before entering the record service; `record-crc-omitted` skips `CustomCodec::seal`. Public append and prepare wrappers are not valid mutation sites when typed internal calls bypass them. Expected state remains the correct state. Every control must return normally and differ in observable record/media state; blocked execution is not control credit.

## Execution ownership

`//replacement/settings_storage:custom-oracle-qualification -- --joined-only` selects the joined bank/custom/record native subset after canonical-source, combined-artifact and property-artifact admission. It uses the same case producer, cached observations and package comparator as the complete qualification. The result label is `typed-settings-storage-joined-native-subset`, and `current_gates_completed` remains false.

The subset executes ten stock witnesses, ten owned witnesses and the refresh-, append- and CRC-omission controls. It does not replace the complete bank matrix, the application-appends-bank and close-appends controls, cross-kind preemption, EE dispatcher, custom lifecycle or system qualification. Omit `--joined-only` for the unchanged complete path. `--plan` cannot be combined with this execution subset.

`--stock-runner PATH` selects the runner for the stock role: the bank-stock and bank-stock-refusal cohorts and, when `--joined-stock-runner` is absent, the joined stock rows. It defaults to `--runner`. Bank-owned, joined-owned and every control cohort run under `--runner`. This keeps retained stock observations on their original runner identity while owned and control observations run on the current runtime.

`--joined-stock-runner PATH` overrides the joined stock rows alone and is accepted in both scopes. Its joined-only fallback remains `--runner`; its full-path fallback is the stock runner. Every runner the attempt uses, and all compiled control BIN/symbol inputs, are frozen and hashed in the review packet. Rejudging retained observations does not change their runner identities.

`--focus preemption`, `--focus ee` and `--focus custom-lifecycle` select one focused execution scope: cross-kind preemption with the unlock-before-copy control, the EE dispatcher equal and different-old-value device-order cases with the seven dispatcher controls, or the custom lifecycle case pairs with the refresh-, correction- and defaults-omission, compiled-defect and boundary controls. A focused result labels itself `typed-settings-storage-focused-<gate>`, records that gate alone in `gates` and keeps `current_gates_completed` false. `--focus` cannot be combined with `--joined-only`, with `--plan`, or with `--joined-stock-runner`, and an unknown or repeated gate fails before any input is read. Omitting every scope flag keeps the complete path, which requires all gates.

The current joined subset passes ten stock witnesses, ten owned witnesses and all three executed semantic controls. The final attempt reused 21 observations and executed only the two new compiled fault artifacts. This is subset acceptance with `current_gates_completed:false`, not complete settings/storage or live caller-frame acceptance.

The manual `//replacement/settings_storage:close-append-purpose-tests` takes ten `--test_arg` values in order: canonical DAT, image4, loader A, loader B, image5, plain, image2, control BIN, control symbols and control ELF. Its inputs are owner-supplied firmware and the source-bound close-appends control artifact.
