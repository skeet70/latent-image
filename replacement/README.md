# Replacement firmware packages

Owned X-M1 replacement code is built through the existing Bazel/Nix graph. Each package stays separate so the shared build declarations change in one place.

- [`toolchain/`](toolchain/README.md): the pinned `armv7r-none-eabi` rustc, its `core` and `compiler_builtins`, and the `xm1_rust_staticlib` / `xm1_rust_elf` macros.
- [`abi/`](abi/README.md): the #119 build and ABI qualification, including the bounded native case, the ABI defect control and the facts #120/#123 consume.
- `first_stage/`: the owned first-record startup staged at slot offset 0x6000 by `//host/firmware:build-first-stage`, with the stock record-1 helpers retained. The correct candidate's natural-reset handoff witness passes on the public runtime pin (E-FIRST-STAGE-PUBLIC-HANDOFF-150) and on combined SDK `97a6ebe` (E-FIRST-STAGE-COMBINED-SDK-HANDOFF-150). On that combined SDK the faulty-handoff and mismatched-image controls fail at their intended checks and the staged DAT cold-boots to SHOOTING MENU (1, 5, 2) (E-FIRST-STAGE-COMBINED-SDK-MENU-CONTROLS-150). The earlier private YIELD-corrected runtime results are E-FIRST-STAGE-NATURAL-HANDOFF-150 and E-FIRST-STAGE-MENU-CONTROLS-150. Full replacement startup, runtime retirement and hardware startup remain separate.
- `secondary_stage/`: the owned record-2 startup for [#135](https://github.com/skeet70/latent-image/issues/135), staged at record-2 slot offset `0x400` (guest `0x10400`) by `//host/firmware:build-secondary-stage`. The [startup inventory](../reports/replacement-inventory-baseline.md#owned-record-2-source-increment-135) records the service ABI and the loader-B register evidence. The schema-3 cohort accepts all five retained and five owned scenarios, four endpoint comparisons and the intended publication/stack fault refusals (`E-SECONDARY-STAGE-SCHEMA3-SCENARIOS-150`). The retired-stock-fetch control is refused at core1 fetch of `0x12960`, before startup handoff or loader-B entry, and the public schema3 consumer refuses its receipt (`E-SECONDARY-RETIRED-FETCH-CONTROL-150`). This does not qualify full startup or hardware.
- `loader_prefix/`: [#136](https://github.com/skeet70/latent-image/issues/136) compiles the secondary startup and loader-B core-1 prefix into one record-2 image. Natural completion orders the original store and committed readback before core1 exit; held completion observes four post-gate zero loads without a store or endpoint; delayed completion preserves the original store and veneer context; non-one completion commits/readbacks `0x400a0000`. Frame, vectors, physical/virtual views and all 22,112 zero-store words agree. The q5 pre-prefix failure remains history (`E-LOADER-B-PREFIX-INITIAL-REFUSAL-150`), not the current verdict. Seven discriminating prefix fault guests are refused at the intended write-confinement, retired-fetch, exit-vector, saved-frame, core-refusal, fill and stack boundaries. Explicit injected-invalid-core and zero-accepting-predicate scenarios executed and produced negative evidence; J2 removed both scenarios and the predicate fault image.
- `interface_initializer/`: a distinct successor to the core1 prefix, covering the complete `0xd0430` interface/descriptor initializer through preexecution `0xd0ab0`. ## General heap production staging

`//replacement/general_heap:general-heap-image` builds the original arena variant; `general-heap-recipe-image` selects ceiling `0xbe1a00` instead of `0xbf1a00`. Both charge state to the arena prefix and keep the 32-byte guard. The linker fails on carrier overflow without selecting a relocated fallback. `//replacement/general_heap:general-heap-tests` contains host-only source/artifact/header/geometry/fetch controls. `heap-bridge-replay` consumes the admitted lifetime tape through the production stock bridge.

`//replacement/general_heap:general-heap-host-tests` and `general-heap-recipe-host-tests` build the pinned Nix host-test derivations for the original and recipe ceilings. Each runs the behavioral Rust oracle inside the derivation and exports its Cargo lockfile only after success; these are Bazel build targets, not separate Cargo test commands.

`//replacement/general_heap:stage-general-heap` takes `SOURCE_DAT IMAGE4 IMAGE5 LINKED_BIN SYMBOLS SCRATCH_DIR OUT_IMAGE4 OUT_IMAGE5 OUT_DAT OUT_CONTRACT` after its Bazel-supplied encoder/rebuilder/decoder arguments. Inputs must match canonical X-M1 1.50 identities. The scratch directory must exist below `private-data/scratch`. It stages image4 with `Emulation.Image4Staging`, replaces record5 through the existing container machinery, decodes both carried streams and rejects every outside-byte change except the corresponding container checksum.

The schema1 contract records canonical identities, staged image paths/digests, candidate DAT digest, five disjoint carrier/immutable intervals, the separately mutable sentinel at `0x89d4f8`, fixed stock entries, all symbols and sized function roots, owned instruction PCs, literals and emitted frame/call boundaries. Backend geometry and state/pool extents come from the linked `XM1_HEAP_METADATA` object and must match `Tlsf<'static,u32,u16,17,16>`, 16-byte granularity, the 16-byte stock prefix and stock alignment 8. Runtime consumers must reject stale owned bytes, fetches outside the derived instruction set and carrier writes other than admitted image publication. The sentinel starts at zero before first allocation and lies below phase0 clearing.

The linker scatters owned code across the retired carriers with `--enable-non-contiguous-regions`: rlsf resize/allocate and the stock resize path are pinned to the resize carrier, backend initialization to the free carrier, and the remaining text spills from the malloc carrier through the bin, resize, trim and free carriers. `memcpy`, `memmove` and their AEABI forms resolve to the retained stock memmove at `0x89d908`; stock lock, unlock and that memmove are the only admitted external callees. The standalone image carries no native GlobalAlloc shims, because with them the owned text exceeds the carrier union. The `allocator()` API in the accompanying rlib exposes the same backend through `Allocator` and `GlobalAlloc` over the fixed arena-prefix state, sentinel and retained lock, so a Rust consumer links those front ends into its own image.

Intentional redesigns are checked calloc multiplication instead of wrapping, oversized resize rejection before locking instead of a leaked recursive depth, minimum nonnull-on-success zero requests, and trim always returning zero instead of releasing top backing. Stock `payload-4` remains a boundary tag with `PREV_INUSE=1`; its decoded usable extent must stay inside the allocation. Native Layout front ends do not carry that stock prefix. The unchanged graphics forwarding adapters and callback table words depend on the patched stock addresses. Cold-boot ownership, runtime guard coverage and retained lock semantics remain admission conditions; source admission alone is not natural-run or silicon qualification.


## Selected volatile bank publication groups (#128, #129)

`//replacement/bank:bank` remains the standard archive. `bank-modal`, `bank-lifecycle` and `bank-modal-lifecycle` compile the same crate root with independent `rb_modal_scoped` and `rb_lifecycle_scoped` cfg selections. The standard archive stages neither optional group's modules. The matching `//host/firmware:ram-push-{modal,lifecycle,modal-lifecycle}-relinker` filegroups supply wrappers setting `RB_PUBLICATION_GROUPS` at the shared script boundary. The builder accepts exactly `--ram-push-variant lifecycle`, `--ram-push-variant modal75` or `--ram-push-variant lifecycle,modal75`; ordinary `--ram-push` remains the default.

Every selected ABI5 package retains 131 setup records. Standard has 223 publications, 92 activations and allocation `0x1dc98`; modal75 has 224/93/`0x1dcb8`; lifecycle has 226/95/`0x1dcd8`; the composed package has 227/96/`0x1dcf8`. The modal-only allocation derives from 32-byte installer growth. Lifecycle and composed installers share an aligned minimum extent; the composed allocation includes a distinct extra 32-byte zero tail. The closed manifest schema is unchanged; allocation size distinguishes the selection. The linker defaults to 223 records and accepts an explicit selected count. The host layout test pins the default archive to its frozen f0b8386/#133 SHA-256.

Lifecycle and composed package selection currently refuse with exit2 before reading build inputs or invoking the toolchain. Their three publications and cfg-gated save/media-permit veneers must be supplied by the lifecycle cutover. The group metadata does not make those incomplete package selections executable.

Lifecycle logical publications 223..225 replace the call sites `0x00e99e8c`, `0x00e6a754` and `0x00e6bb90`, in that order. The modal group appends logical publication 223 when selected alone, or 226 when composed, replacing stock word `0xe92d4ff0` at `0x00bfb028` with an unconditional A32 branch to linked `rb_modal_entry`. Modal is always the final activation, so rollback restores the stock modal entry before lifecycle and dependent bank tables. The builder refuses a different stock push, a duplicate or missing hook, an unaligned or out-of-domain branch, an executable target outside bank storage, or a source word overlapping the allocation. The 56-byte entry seam selects owned dispatch only for full-word controller 75; other controllers recreate `push {r4-r11,lr}` and resume at `0x00bfb02c`. Both paths restore incoming flags and scratch register before handing off.

The scoped builder emits `modal-scope.json` beside the unchanged manifest. It records controller 75, fixed stock entry/resume, `global_admission=false`, the runtime hash and the bound ELF hash. Complete ELF function extents for `rb_modal_entry`, `rb_modal_dispatch`, `rb_modal_call_prehook` and `rb_modal_call` must be aligned executable `.text`, match the symbol listing and match `linked.bin`; the seam must be exactly 56 bytes. Scoped source identity also includes the modal Rust/assembly and wrapper.

The shared relinker emits `kernel-text.bin` by extracting `.text` from `kernel.elf` into a separate output file. Native consumers bind that text artifact, the ELF and `kernel.syms` independently.

`BankAllowlistComposition` parses the unchanged base allowlist and selected additive fragments through the checker's typed parser, in canonical lifecycle then modal75 order. The fragment paths are `menu/recipe_bank_allowlist.lifecycle.json` and `menu/recipe_bank_modal_allowlist_fragment.json`. It refuses missing, reordered or unselected sources and duplicate capabilities. The builder emits `bank-allowlist-input.json`, retaining the exact base bytes when no group is selected, and records its `bank_allowlist_composed_sha256` alongside the selected source-file identities. ## Owned menu engine, increment 2 (#128)

Under `--cfg rb_menu_engine_owned` the bank crate links `menu_engine/adapter`: one RAM-push publication replaces `0xbf95c8`'s first word (`0xe92d4818`) with a branch to `rb_menu_engine_entry` (`adapter/entry.S`). The entry calls `rb_menu_engine_apply`, which decodes the block and the last-move pair into the one in-progress `EngineState`, the bank-data static `ENGINE_STATE`, decodes the stage event and runs `apply` on it in place with stock services: before each call it writes the changed block words, and `kind_switch`, `seek`, availability, initial row and notify reach `0xbfa234`, `0xbfad04`, `0xd52684`, `0xd588b8` and `0xd5b350` through engine-region trampolines; `kind_switch` and `seek` decode the block back into the same state. The engine reaches the state through a zero-sized handle (`StaticState`), so no frame holds an `EngineState` or a pointer to it; a nested entry while an event runs falls back to stock. `token_past_rows` reads `values + 8*row` volatilely through the record side table. A stock answer or block that does not decode after the first call enters `rb_menu_engine_guard_failure`, a `nop` followed by a branch-to-self loop, whose entry the pair runs trace. On `NotOwned` the entry restores its registers, runs `0xbf95c8`'s own prologue and resumes stock at `0xbf95cc`, so the fallback's call to `0xbfa234` returns to `0xbf95d4` and every service call returns elsewhere. The engine and its generated tables are `no_std` and free of core panics, division and compiler_builtins; the entry assembly supplies `__aeabi_memcpy*` and `__aeabi_memclr*`.

`apply` and the checker's `MenuEngineClass` refuse, before any call, an event whose open node's tree rows differ from the block's total rows (`NotOwned::RowTotal`), and a push from a row whose child is a package node (`NotOwned::PackageChild`). The guest archive's tree is the menu tables composed with the installed package's rows: `menu-engine-tree --package-plan BANK-PLAN.json` reads the recipe-bank builder's own `bank-plan.json` writes for the shooting root `0x0078ea98` (its republished values and labels arrays, through their terminators), keeps the 33 decoded rows and appends rows `0x7d` (EDIT/SAVE CUSTOM SETTING, label `0x846`) and `0x7e` (SELECT CUSTOM SETTING, label `0x847`), giving the 35 rows stock sees on the RAM-push route. Their children are the package's slot and selection nodes, which are not decoded nodes, so the tree gives them `RowChild::Package`. They take availability from the stock `0xd52684` query like every row of the root (`Availability::Queried`), so the tree adds no availability of its own. The host oracle keeps the stock tree.

The publication group `menu-engine` composes only with `modal75` (`RamPushLayout.modalEngineBankVariant`, 225 publications). Its allocation ends at `menuEngineRegionStart base + menuEngineRegionExtent`, a 64 KiB engine region past the installer. `host/firmware/build-recipe-bank-ram.sh` (selected by `build-recipe-bank-modal-engine-ram.sh`) renames the engine's input sections to `.menu_engine.*` and `menu/recipe_bank_ram_engine.ld` places them in that region, so the bank window and the other variants' links are unchanged. `--menu-engine-owned`, with `--ram-push-modal-scoped` and `--modal75-owned-archive`, selects this package for an archive built with `-C llvm-args=-min-jump-table-entries=4096 --cfg rb_modal_scoped --cfg rb_modal75_owned --cfg rb_menu_engine_owned` (the other flags as `//replacement/bank:bank-modal`); the modal lifetime guard accepts it, with publication counts derived from the variants in both `Emulation.ModalObservation` and the bridge. The jump-table flag applies to the whole bank crate of that one `rustc` invocation, so the owned role's modal75 dispatcher and every other bank Rust function are compiled without jump tables, unlike the stock role's `bank.a`. Without jump tables `check-bank-allowlist` follows every branch of the engine; `menu/recipe_bank_menu_engine_allowlist_fragment.json` declares the engine stores it cannot bound, by the mangled names of that build: stores to the engine `Machine`'s flags or a result on `rb_menu_engine_apply`'s stack, array stores into `ENGINE_STATE`, the block writes at `0x009571d0` and the depth-1 and depth-2 snapshot stores. With them the picker-table build at `0x00c40000` has no violation.

The builder bounds the stack statically for this package (`host/firmware/EngineStack.hs`, `//host/firmware:engine-stack-tests`) and fails the build past the limit. A function's frame is the sum of the stack reservations on its reachable instructions and its depth adds its deepest callee; calls into stock count nothing, register branches resolve through movw/movt or literal constants (`rb_modal_call`'s action call counts as stock), and an sp write other than an immediate adjustment, a pop or a restore from r11 refuses. The headroom below `0xbf95c8`'s entry is 2680 bytes: task 1's stack is `[0x00a4c200, 0x00a4ce00)` (the task identity of `picker-runs-2/picker-15-owned-2`, E-RECOVERY-MAINUI-CREATE-150) and the menu-oracle receipts enter `0xbf95c8` at sp `0x00a4cc78`. 1024 bytes are kept for stock callees, four times the deepest traced stock site under `0xbf95c8` in those receipts (248 bytes, `0xd52684`), so the engine's depth from `rb_menu_engine_entry` plus the owned modal dispatcher's from `rb_modal_entry` must stay within 1656 bytes. The picker-table build measures 808 + 164 bytes. The 1024-byte margin is an estimate until the pair runs measure task 1's high-water mark. The static bound does not include bank frames reached through `rb_modal_call`'s action targets or through the `0xd526fc` and `0xbfa800` bank hooks.

Trace sites may take options (`[address, label, {"reads": [[start, length], ...], "lr": true, "sp": true}]` in a trajectory, `"reads"` in a `--menu-observe` site): the bridge records each read at every entry, and the e2e keeps a hit's lr only for a site with reads or `"lr": true` and its sp only for `"sp": true`, so receipts of configs without options are unchanged. `emulation/menu-engine-pair-trajectories/` renders the pair inputs: `picker.jq` adds the engine reads (block, last-move pair, root, depth-1 and depth-2 snapshot areas, and task 1's whole stack) and sites (stage entry `0xd4dd2c` with the block and sp, kind switch `0xbfa234` and seek `0xbfad04` with lr, event post `0x0063270c`, and in the owned role the guard trap) to a picker trajectory, and `oracle.jq` turns a menu-oracle config into a RAM-push trajectory over crawl-5's landings. `//replacement/modal_runtime:menu-engine-pair-check --package-plan` derives each stage event's class from the composed menu tables, its registers and its block (`MenuEngineClass`, independent of the adapter), fails the owned role on a guard-trap entry or, in a segment before the receipt's `ram-unload` phase, on a kind-switch entry returning to `0xbf95d4` for an owned class (unload restores `0xbf95c8`'s stock word, so later segments run stock in both roles), and requires both roles' engine reads and `0x1d` posts to be equal. It also recomputes the stack bound from the owned receipt's relinked `kernel.elf` and, in both roles, fails a stage entry whose sp less the bound plus the margin falls below `0x00a4c200`, and reports the lowest task-1 stack word that changed across the run as the measured high-water mark, failing if it lies below the lowest such floor; the stack read is not compared between roles. `//replacement/modal_runtime:menu-engine-pair-tests` covers it on synthetic input. `modal-settings-compare` and `render-compare` complete each pair. `RuntimeRelocationCompare` refuses the menu-engine package.
