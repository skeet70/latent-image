# Replacement firmware packages

Owned X-M1 firmware code and its host tooling use the repository's Bazel/Nix build. Start with the workflow for the subsystem you are changing.

## Build and inputs

Run commands from the repository root through [host-build](../build-support/README.md#commands):

```sh
devenv shell -- host-build build //replacement/abi:pilot-image
devenv shell -- host-build test //replacement/abi:pilot-abi-tests
```

The [Rust toolchain guide](toolchain/README.md) owns compiler provenance and build macros; the [ABI guide](abi/README.md) owns the bounded ARM qualification. Existing package guides cover the [record validator](validator/README.md), [retained row-availability service](service/README.md) and [render adapter](render_adapter/README.md).

Emit retained-kernel capability metadata as `XM1_KERNEL_BOUNDARY` from the consuming image root. Property/menu images use `BASIC_BOUNDARY`; time-services uses `FULL_BOUNDARY`, whose wait/signal entries accept retained semaphore creation words. Property admission verifies every named function against the ELF and coalesces only exact code aliases. Unequal overlapping extents remain rejected.

`devenv shell -- run-output exec --label linked-image-bytes -- host-build run //host/firmware:owned-image-bytes` reports bytes by crate and section for the linked menu and render variants.

Stagers require their declared canonical X-M1 1.50 inputs, not an arbitrary previously staged candidate. Firmware and generated artifacts remain in ignored `private-data/`; use a named `private-data/scratch/` directory or `private-data/verify-candidate/runs/` for new outputs. Individual commands specify whether directories must already exist or be fresh. Guest execution uses the shared [emulator slot](../build-support/README.md#commands), normally `XM1_EMULATOR_SLOTS=1`; file-only admission and comparison do not execute firmware.

## Linked shim admission

Each owning unit's `shims.json` is the authoritative family declaration. [The register](shims.md) is generated from those declarations and `shim-images.json`; its composition and reference tables are the coverage matrix. The checker reads the actual ARM ELF symbol bindings, retained relocation records and constant call targets, checks each expected ELF identity and qualified binary pin, and refuses missing declarations, exports, retained imports, contradictory bindings and unsupported removal claims. A source filename or wildcard is not link evidence.

The checker independently discovers firmware-owning directories from actual BUILD metadata and source kinds, including Rust cross-toolchain rules and Nix/native ARM-link producers. It resolves the startup packager's declared lists, recursive immutable aliases, parentheses and concatenations. Root BUILD metadata method invocations and indexed or augmented assignments are conservatively refused before resolution, including mutations through aliases. Unresolved, cyclic or unsupported relevant expressions fail closed. `--build-root` names that source checkout separately from a runfiles artifact root. A new firmware unit or RootPackage constituent without a declaration is refused. Required exports must be global definitions inside allocated image sections; absolute retained imports and untyped global entries remain distinct declared mechanisms.

```sh
devenv shell -- run-output exec --label shim-linked -- bash -c 'host-build run //replacement/shim_check:shim-check -- --receipt-output "$XM1_RUN_RESULT/checker.json"'
devenv shell -- run-output exec --label shim-contracts -- host-build test //replacement/shim_check:shim-check-tests //tests:research-contracts
devenv shell -- run-output exec --label shim-register -- host-build run //replacement/shim_check:shim-check -- --render replacement/shims.md
```

`result.link_admitted` reports the declared link boundary, not firmware acceptance or removal eligibility. Each family reports its remaining state and a three-valued removal predicate. `unestablished` remains pending. `removed` requires an absent linked mechanism, established caller closure and direct owned API use, plus a digest-bound comparison receipt whose compared units are exactly the checked image's participants. Declared consumers must participate before removal. Ownership alone supplies none of those predicates. Frozen standalone RTOS bodies remain references; current platform aggregates supply their linked evidence. The startup RootPackage composes fourteen constituent ELFs across 33 declared input files through its existing contract, not a fictitious aggregate ELF.

Adding a composition or migrating a family is a declaration-data change: name its exact current symbols or retained-entry/layout/publication requirements, include its artifacts in `:linked-images`/`:catalog-data`, record the qualified expected identities, and regenerate the register. `--artifact-inventory PATH` emits non-admitting observations for this migration; it neither accepts comparisons nor updates pins. `//tests:research-contracts` invokes the real checker and rejects a stale generated register. Dynamically supplied callback and caller closure remain separate qualification obligations.

Definite retained-reference analysis follows A32 instructions, relocation targets and tracked constants, including the taken and fallthrough edges of conditional PC writes. Unknown register targets, nonliteral loads, Thumb execution and rejected paths do not establish exhaustive caller closure. Power's record-helper image binds its actual helper exports and three kernel imports; the absent NAND/property/pipeline/task/modal/scanout clients, assembly residues, OSAL slot consumers, callback registry and 88 leaf-service producer entries remain explicit nonlinked obligations. Reference-only symbol assertions are checked for absence from the owner's current images.

## Fixed owned image

`replacement/fixed_image/layout.json` defines the layout constants. `//replacement/fixed_image:contract` exposes them through `Replacement.FixedImage.Layout`; `//replacement/fixed_image:layout` exposes the Rust rlib `xm1_fixed_image_layout`. The contiguous reserved RAM range is `[0x00a9fa00, 0x00bf1a00)`, ending before stock image 5. Its 32-byte record header precedes the linked body at `0x00a9fa20`; flash starts at `0x00900000` and holds at most eleven 128 KiB blocks.

Link a subsystem through `rlib_deps` into the image's existing Rust root, not a second fixed-range image. Generate the linker script with its retired in-place extents and include `//replacement/fixed_image:memory-region` (`fixed-memory.ld`) inside `MEMORY`. That include declares `OWNED_FIXED`. Assign body sections and in-place retired sections in the same `SECTIONS` command and perform one final link. Keep `.data` in the fixed region with identical load and run addresses. Put `.bss` in a distinct `NOLOAD` section, word-align its bounds, export `__fixed_bss_start` and `__fixed_bss_end`, and assert its end does not exceed `ORIGIN(OWNED_FIXED) + LENGTH(OWNED_FIXED)`. Extract only fixed-region file-backed sections into the body binary; in-place sections belong to their container images. The body starts exactly at `ORIGIN(OWNED_FIXED)`, including any leading alignment padding. In-place regions require their subsystem's retirement evidence.

Export `__fixed_body_start` at the first fixed-region file byte and `__fixed_body_end` immediately after the last. The stager requires start `imageBase + headerBytes` (`0x00aafa20`) and end equal to start plus `BODY_BIN` length. Use the BSS symbols from that same final link.

Saclac admission permits `__power_cpu_end` as endpoint metadata only for a data relocation to that exact zero-sized ELF symbol at the admitted allocated `.bss` end. The linked `.bss` must match the admitted section, and the symbol must be absolute or belong to that section. This exception does not extend owned storage, instruction targets or access bounds.

## Lens transport

[`lens_transport/`](lens_transport/) contains the allocation-free lens wire engine, bounded packet codecs, serial/DMA and timer programming, and firmware publications. Its host scenarios supply wire bytes and timer expirations explicitly. `//replacement/lens_transport:host-tests` covers the public request/completion lifecycle; `//replacement/lens_transport:codec` and `//replacement/lens_transport/native:codec-suite` provide the bounded stock-byte/owned-A32 comparison source.

The native suite takes `RUNNER CACHE OUTPUT IMAGE4 OWNED_CODEC_ELF`. It authenticates the X-M1 1.50 image and selected function extents, runs request constructors to their return with the event-3 publication edge at `0x006bf218` modelled as a synthetic returning interface, and compares parser results, transmitted bytes, queue records and the caller-owned bytes past each frame's initialised extent. It covers the `0xa55a3cc3` response acceptance, which stock gates on the machine words at `0x00955dd4` and `0x00955dd8` reading 6 and 12, and page frames from a three-byte payload up to `0x1000` bytes against the `0x820`-byte transmit buffer at `0x4096d000`. It does not establish physical timing, endpoint availability or whole-actor qualification. The firmware archive requires the owned Power critical-section/resource-route and RTOS IRQ providers, plus exclusive reservation of serial 2, DMA 2/3, timer 11, IRQs 31/94 and their scratch windows. ## Power lifecycle

[`power_lifecycle/`](power_lifecycle/) is two crates. `xm1_power_services` (root `src/services.rs`) is the services leaf: OSAL and delay primitives, the timer services, queue construction, resource routes, the serial driver, area 2, standby, the shutdown path with its task 6, 7 and 8 executors, the settings and storage shutdown actors, a typed callback registry and the dispatch of stock's installed-callback words through it. `:services-host-tests` runs its host tests and `:services-arm` builds the ARM rlib.

The application crate (root `src/lib.rs`) holds the mode frontends, audio release, capture task 3 and the recording path (the task 43 machines, scan, profiles, statistics and completion callbacks) over a shared guest address space. `:host-tests` runs its host tests and `:arm-core` builds the ARM rlib. It cannot link: the ARM rlib leaves over a thousand `xm1_power_record_helper_*` symbols undefined that no unit provides, 34 sites call a guest word as a function pointer instead of resolving it through the leaf's registry, and the unit's review findings are open. Nothing links either crate into a firmware image, and the event-flag carriers the application needs from the RTOS platform are not in the platform images.

## saclac

[`saclac/`](saclac/) contains the task-43 driver and retained dispatcher model. The native router at `0xefcb88` dispatches to the persistent `saclac/root` aggregate; the generic dispatcher at `0xefca6c` still links stock's 37 machine tables and actions and is not an accepted complete cutover. The driver at `0xf01bc8` uses `xm1_kernel` queue reception, preserves retained receive scratch and command blocks, and releases each received block before dispatch. Oversized commands and receive failures call the retained fault reaction without dispatch. `//replacement/saclac:saclac` is the rlib; `:saclac-image` links the image-5 replacement. `:host-tests` exercises engine and intake contracts.
