# Replacement firmware packages

Owned X-M1 firmware code and its host tooling use the repository's Bazel/Nix build. Start with the workflow for the subsystem you are changing.

| [Settings and record storage](settings-storage.md) | Property service staging/qualification, record-store carrier, native oracle and generated counterexamples |
| [Menus and RAM packages](menus.md) | Bank publication groups, menu-engine inputs, packaging and pair comparisons |

## Build and inputs

Run commands from the repository root through [host-build](../build-support/README.md#commands):

```sh
devenv shell -- host-build build //replacement/abi:pilot-image
devenv shell -- host-build test //replacement/abi:pilot-abi-tests
```

The [Rust toolchain guide](toolchain/README.md) owns compiler provenance and build macros; the [ABI guide](abi/README.md) owns the bounded ARM qualification. Existing package guides cover the [record validator](validator/README.md), [retained row-availability service](service/README.md) and [render adapter](render_adapter/README.md).

Stagers require their declared canonical X-M1 1.50 inputs, not an arbitrary previously staged candidate. Firmware and generated artifacts remain in ignored `private-data/`; use a named `private-data/scratch/` directory or `private-data/verify-candidate/runs/` for new outputs. Individual commands specify whether directories must already exist or be fresh. Guest execution uses the shared [emulator slot](../build-support/README.md#commands), normally `XM1_EMULATOR_SLOTS=1`; file-only admission and comparison do not execute firmware.

## Fixed owned image

`replacement/fixed_image/layout.json` defines the layout constants. `//replacement/fixed_image:contract` exposes them through `Replacement.FixedImage.Layout`; `//replacement/fixed_image:layout` exposes the Rust rlib `xm1_fixed_image_layout`. The reserved RAM range is `[0x00ba0000, 0x00be0000)`. Its 32-byte record header precedes the linked body at `0x00ba0020`; flash starts at `0x00900000` and holds at most two 128 KiB blocks.

Link a subsystem through `rlib_deps` into the image's existing Rust root, not a second fixed-range image. Generate the linker script with its retired in-place extents and include `//replacement/fixed_image:memory-region` (`fixed-memory.ld`) inside `MEMORY`. That include declares `OWNED_FIXED`. Assign body sections and in-place retired sections in the same `SECTIONS` command and perform one final link. Keep `.data` in the fixed region with identical load and run addresses. Put `.bss` in a distinct `NOLOAD` section, word-align its bounds, export `__fixed_bss_start` and `__fixed_bss_end`, and assert its end does not exceed `ORIGIN(OWNED_FIXED) + LENGTH(OWNED_FIXED)`. Extract only fixed-region file-backed sections into the body binary; in-place sections belong to their container images. The body starts exactly at `ORIGIN(OWNED_FIXED)`, including any leading alignment padding. In-place regions require their subsystem's retirement evidence.

Export `__fixed_body_start` at the first fixed-region file byte and `__fixed_body_end` immediately after the last. The stager requires start `0xba0020` and end equal to start plus `BODY_BIN` length. Use the BSS symbols from that same final link.

`//replacement/fixed_image:check-fixed-image ALLOWLIST ELF BODY ENTRY OWNED_STACK_BYTES OUTPUT_JSON` applies the bank checker's shared ELF-relocation and direct-transfer admission to a fixed-only link. Link with `--emit-relocs`; the checker also verifies fixed section bounds, permissions, body bytes and BSS against that ELF. The allowlist uses schema 2 stock entries and regions. It reports the entry's owned direct-call stack depth against the supplied budget, not retained callee demand or caller/task headroom. The probe uses `probe-allowlist.json`, entry `xm1_fixed_test_entry` and a 48-byte owned budget: its veneer reserves 40 bytes and the emitted Rust observer reserves eight at `0xba0050`. An aggregate link with retired in-place sections needs its subsystem's placement admission as well.

`//replacement/fixed_image:stage-fixed-image` takes `ENCODER REBUILD DECODER SOURCE_DAT BODY_BIN SYMBOLS PUBLICATIONS_JSON FIRST_STAGE_SYMBOLS OUTPUT_DAT`. The tools are `//lz:lz-encode`, `//host/firmware:rebuild-update` and `//lz:fflzd`. `SOURCE_DAT` must already contain `//replacement/first_stage:first-stage-fixed-image`, staged with `//host/firmware:build-first-stage`; `FIRST_STAGE_SYMBOLS` comes from that exact link. The stager derives a build id from the body and publication words and stages it into the first stage's declared build-id word. It refuses a non-placeholder preimage. The JSON is an array of rows with numeric `address`, `old` and `new` words. Equal words, duplicates, unaligned sites, sites outside the image windows and wrong preimages are refused. Image 4 and 5 publications are decoded, patched and re-encoded through the existing record gates; plain-image words use `replace-plain`. The stager adds the stock heap ceiling and phase-0 mode-1 clear bounds itself; those four sites must retain their stock preimages in the source DAT. Do not repeat them in the publication manifest.

The stager places nested encoder and container-tool temporaries under `XM1_RUN_WORK`. Apply each in-place mutation once: include its changed words in the publication manifest against their stock preimages, or stage section content separately and omit those words from the manifest. Do not pre-stage a veneer and then supply its old-to-new row. Do not use the aggregate ELF's flat binary as `BODY_BIN`: extract the fixed sections from that same link, preserving their address gaps, and retain the same symbols for BSS and publications.

The record words are magic `0x584d314f`, load address, total header-plus-body byte length, body CRC-32, build id, BSS start, BSS end and zero. The stager checks the two-block carrier's shipped fill, gates container reconstruction and checks byte-identical reversal of the record mutation and each image's publication mutation. It stages no installer or rendezvous. The first-stage variant loads on core 0 after image 4, validates the bounded header before reading an optional second block, checks CRC and build id, clears BSS, synchronizes instruction visibility and halts on any failure.

The stager writes `OUTPUT_DAT.json` with input-bound sizes, digests and the image safety fields. A linked `XM1_REQUIRES_LENS_SAFETY_CONTRACT` word of value 1 sets `emulator_only` and `lens_safety_contract_required`. Keep `.rodata.XM1_REQUIRES_LENS_SAFETY_CONTRACT` in the linker script when joining a subsystem that exports it; section GC must not discard the marker. `//replacement/general_heap:general-heap-fixed-image` supplies the owned allocator with the same ceiling, alongside its original and recipe variants.

Every package containing the fixed first stage and the owned heap must link `general-heap-fixed-image`, not the default or recipe heap. The stager scans the owned heap carriers in decoded image 4 for version-1 heap metadata and refuses an arena end above `0xba0000`. Failed fixed loads enter the first stage's normal GPIO failure sequence through the labelled fixed-load failure boundary; successful loads add no boot-profile events.

`stage-fixed-image --ceiling-only ENCODER REBUILD DECODER SOURCE_DAT OUTPUT_DAT` stages only the stock heap ceiling for placement measurements. `//emulation:heap-observe --placement prepare|capture|playback|reset-watch --run RUN --update DAT --boot-rom ROM --checkpoint FILE --output DIR` records heap-break high-water and guards `[0x00ba0000, 0x00bf1a00)`. Preparation writes a post-setup live-view checkpoint and its identity; capture and playback restore that checkpoint. `reset-watch` runs the canonical stock DAT from reset and requires one boot fill and no later write into the partition. A high-water within 256 KiB of the fixed ceiling fails. Wi-Fi remains a camera final-pass measurement.

The capture placement route follows the visible shooting-menu cursor to row 20 with a 64-key bound, selects SHOOT WITHOUT LENS ON, closes the menu and drives the half/full shutter inputs. Disabled menu rows need not consume one key each. These cardless input scenarios do not establish heap demand for admitted capture, codec execution, saved-image playback or Wi-Fi. Those remain camera final-pass measurements. E-RAM-PUSH-INSTALL-150 is the existing camera evidence for a resident heap allocation through a shot and playback.

Existing RAM-push routes remain heap-linked until the placement prerequisites and their route's migration are qualified. The boot format does not authorize an internal-flash write or a camera run.

## Lens transport

[`lens_transport/`](lens_transport/) contains the allocation-free lens wire engine, bounded packet codecs, serial/DMA and timer programming, and firmware publications. Its host scenarios supply wire bytes and timer expirations explicitly. `//replacement/lens_transport:host-tests` covers the public request/completion lifecycle; `//replacement/lens_transport:codec` and `//replacement/lens_transport/native:codec-suite` provide the bounded stock-byte/owned-A32 comparison source.

The native suite takes `RUNNER CACHE OUTPUT IMAGE4 OWNED_CODEC_ELF`. It authenticates the X-M1 1.50 image and selected function extents, runs request constructors to their return with the event-3 publication edge at `0x006bf218` modelled as a synthetic returning interface, and compares parser results, transmitted bytes, queue records and the caller-owned bytes past each frame's initialised extent. It covers the `0xa55a3cc3` response acceptance, which stock gates on the machine words at `0x00955dd4` and `0x00955dd8` reading 6 and 12, and page frames from a three-byte payload up to `0x1000` bytes against the `0x820`-byte transmit buffer at `0x4096d000`. The owned write frame stops at `0x81e` payload bytes without a checksum and `0x81d` with one, the two shapes that fit the buffer; a longer frame is refused where the stock body at `0x006bf50c` and `0x006bf5fc` copies past it. It does not establish physical timing, endpoint availability or whole-actor qualification. The firmware archive requires the owned Power critical-section/resource-route and RTOS IRQ providers, plus exclusive reservation of serial 2, DMA 2/3, timer 11, IRQs 31/94 and their scratch windows. The host and ARM builds, the host behavioral tests and the 506-case native differential run pass with no differences; the observation, cache and report live under a named private scratch root, and nothing links the unit into a firmware root yet.

`//replacement/lens_transport:actor` and `//replacement/lens_transport/native:actor-suite` compare the task 99 actor against stock in 109 cases. Each case stages one 24-byte queue-99 record (opcode, sender, destination, length, payload pointer) plus its payload words at `0x0096aff4`, runs the stock dispatcher at `0x006c2b6c` to the loop clear at `0x006c2bc4` (the wake case runs the receive call at `0x006c2b54` to `0x006c2b64`), and runs the owned actor entry against the same record. The stock kernel services are exit-recording or silent bodies at their stock addresses, the reply entries at `0x006bdf44` and `0x006be368` stay stock bytes, and the owned adapter records its effects as the same five-word ring at `0x00204000`. Compared: the effect ring (queue sends, timer starts and cancels, key releases, event flags, diagnostics, detection mode and output, GPIO reset, delays, caller callbacks), the shared publication words at `0x0095e1d0` (available, connected, status and public mode), the actor state word, the message buffer and the `0xfff89000` MMIO window. A caller callback compares its token and whether the status is a rejection: the stock shared reject helper at `0x006c1920` passes its dispatch index in r0, so an accepting call's exact status is not a contract value. Every case also reports the stock handler the dispatcher selects and the number of stock instructions executed inside that handler's authenticated extent, and a case with none fails. Two deliberately wrong owned actor variants, one without the detection IRQ attach and one that suppresses the stop sequence's `0xfff89340` writes, must be reported different.

Cases cover all 17 opcodes in all six states, the contained handlers (Register, Attached, ModeComplete, TeardownComplete), and a queue-empty wake; the suite exits nonzero when any case differs. The reply family runs end to end: the stock parser at `0x006be368` and the owned wire entry decode the same four-byte reply, each decoder's status is staged into that side's `0x730b` actor record, and the four scenarios (valid reply, timeout, invalid reply and the `0xa55a3cc3` gate) compare the actor state word, the shared block and the effect ring. Its result reports the stock parser's executed instructions for each scenario that carries reply bytes and the stock response handler's instructions for every scenario, and a wrong owned wire variant that ignores the machine words at `0x00955dd4`/`0x00955dd8` must be reported different. Acceptance is the decoder status and the actor boundary (state word, shared block, effect ring, MMIO window); the decoder's internal state layout is a diagnostic comparison, reported under `diagnostic_differences` and listed by `//emulation:judge` without changing the verdict, so the actor's state layout stays free. Not compared: physical frames, DMA, serial, interrupts and timing; reply bytes never reach the actor record, only the decoder status; the event-3 publication edge at `0x006bf218` and every kernel service are synthetic returns; the initialization response path in state 1 and the initialization-finished success path are not exercised at the actor boundary; and nothing links the unit into a firmware root. The first two actor results were invalid because of harness defects: the service-stub immediate encoding and the effect-ring record stride were wrong, and the callback and branch-walk boundaries were incomplete. The retained run is the first whose stock side executed every selected handler with the corrected stubs.

The task-99 control modules implement the six-state opcode dispatcher, initialization/response CPU and typed cache/lifecycle interfaces. Restricted initialization uses an externally owned shared readiness flag and timer continuations; task99 can process readiness events while the restricted wait is pending. Timer deliveries retain their allocation identity. Cross-task clients use synchronized coherent publications, and completion effects are exposed after state publication. The Vendor `lens_control_runtime` adapter translates queue-98 command, calibration-read and capability-write transactions into task99 events. `control_root` owns the native task: `Task99Reservations` rejects duplicate timer slots and `Task99Root::initialize` rejects a queue or timer that disagrees with its reservation, then creates queue 99 and stores the actor, outbox and providers before task activation, `xm1_lens_task99_run` enters the synchronous receive/dispatch loop, and `Task99Ingress::try_post` claims only the reserved queue for Power's `LensQueueIngress` hook. `control_callbacks` admits registered completion addresses against RootPackage code regions and releases each at completion; `LensEffects` routes admitted tokens to those addresses, foreign tokens (iris periodic, Power callbacks) to an owned fallback, task wakeups to `xm1_power_set_task_flags`, key releases through `key_ui_native`'s queue 1/7 service, and diagnostics/detection/GPIO to composition providers. `wire_native::install_irq_handlers` gives the wire and timer vectors one installed owner: the queue-98 runtime in firmware, or the bounded `abi.rs` transport, which installs its own handlers only while initialized and removes them on unregister. `//replacement/lens_transport/native:root-components` supplies the entry object, the admission object and `control-roots.ld` for each RootPackage link; the admission genrule defines `xm1_lens_root_{a,b}_package_admitted` only when every `control-roots.ld` address matches the same symbol in that domain's `carriers.json` entries. Whole-actor ownership still requires the Vendor queue98 startup root (the 6b8f78 context body, detection bind and queue98 canonical state), and both RootPackage compositions binding Power/profile/detection/key providers. Those are software dependencies, not physical-device boundaries. The pinned FULL emulator supplies no stateful R4 cache geometry or maintenance model; native cache admission remains closed. No whole-CPU, hardware-quiescence or physical-device law qualification is implied.

`Task99Client::begin_snapshot` returns an allocation-free `SnapshotRequest` that can be retained between task polls. `try_complete` returns `None` until a matching task99 completion is delivered; dropping the ticket releases its mailbox registration. The asynchronous `snapshot` method uses the same registration and decoding path.

## Develop pipeline

[`develop/`](develop/) holds the develop transaction framework, the image, sensor, processing, output, metadata and font pipeline stages, and the portable calibration and font cores other units mount. `//replacement/develop:develop-candidate` links the whole unit for ARM with no duplicate or undefined symbol. `//replacement/develop:portable-cores-tests` executes the calibration and font cores, including the shaping capacity and classification boundaries; `//replacement/develop:model-catalogue-test` keeps every `model/*.hs` module named by the stage catalogue.

`//replacement/develop:model` builds all 61 Haskell scenario modules under `develop/model/`, one or more per pipeline stage, and `:develop-qualification` links it. `develop-qualification --list IMAGE4 IMAGE5` reports 56 stages and 7,974 cases against 307 stock extents: 5,133 cases name an entry outside the develop stock region `0xe40000..0xeb2000` and none name an address inside it without a range row. The thirteen `operation-predicates` extents the decomp index lacks are supplied from the listing; the outside-region cases still need the stock application image mapped, so none of the 5,133 is runnable yet. The stage harness maps the image-4 and kernel-0 extents a stage entry enters, declares each callee from the listing, and keeps the wire and case artifacts of non-passing cases under `$XM1_RUN_WORK` with the verdict under `$XM1_RUN_RESULT`. `--stage NAME LIMIT RUNNER ...` builds each case's stock and owned side from the same scenario, admits it through the native case contract and compares the observations.

The stage smoke declares each side's entry call closure rather than every candidate symbol, and derives case ids from the sanitized scenario name with the full name in the provenance. The 94-case ObjectAllocator stage passes 94 of 94 with no unit difference: the stage model now places the fifth and later arguments on the entry stack (stock `acquire_object` reads the caller cell at `0x00e46b30` through its frame pointer), maps the diagnostic logging page stock `append_stream_text` reads at `0x0072666c`, and supplies the second notified waiter's task priority that stock reads at `0x007245ac`. The image-geometry border law matches stock `configure_borders` at `0xe4f3b0`: the non-packed right tail starts at `max(next eight-byte boundary, width & ~7)`, and the packed right edge clears twelve-byte groups to `width/12`. The two `transforms` cases that fail to generate use a 96x12 copy packet; stock `hw_register_block_fff6f000_configure` at `0x68d9c0` returns `0xffffffe2` unless width and height are both multiples of eight, so those success-path packets are wrong and the law is right. The low-memory words some scenarios depend on come from one warm-attach observation (`checkpoint-low-prefix` over an SDK checkpoint), not from cold-boot state.

## Power lifecycle

[`power_lifecycle/`](power_lifecycle/) is two crates. `xm1_power_services` (root `src/services.rs`) is the services leaf: OSAL and delay primitives, the timer services, queue construction, resource routes, the serial driver, area 2, standby, the shutdown path with its task 6, 7 and 8 executors, the settings and storage shutdown actors, a typed callback registry and the dispatch of stock's installed-callback words through it. `:services-host-tests` runs its host tests and `:services-arm` builds the ARM rlib.

The application crate (root `src/lib.rs`) holds the mode frontends, audio release, capture task 3 and the recording path (the task 43 machines, scan, profiles, statistics and completion callbacks) over a shared guest address space. `:host-tests` runs its host tests and `:arm-core` builds the ARM rlib. It cannot link: the ARM rlib leaves over a thousand `xm1_power_record_helper_*` symbols undefined that no unit provides, 34 sites call a guest word as a function pointer instead of resolving it through the leaf's registry, and the unit's review findings are open. Nothing links either crate into a firmware image, and the event-flag carriers the application needs from the RTOS platform are not in the platform images.

## saclac

[`saclac/`](saclac/) is the task 43 engine: the owned dispatcher at `0xefca6c` and machine 0's router at `0xefcb88` over stock's 37 machine tables, with every action still a stock word. `//replacement/saclac:saclac` is the rlib for the owned image; `//replacement/saclac:saclac-image` links it in place at the two stock extents for the comparison. `//replacement/saclac:host-tests` runs the core's tests, and `//replacement/saclac:saclac-suite RUNNER OUTPUT IMAGE5 OWNED_ELF WRONG_ELF` runs the stock-against-owned comparison, the wrong-r3 image as its control, and writes the report and its verdict.

The two extents are declared once, in `Replacement.Saclac.Artifact.extents`:

- `//replacement/saclac:saclac-extents linker-script` prints the linker script the image links with; `:saclac-extents census-sites SITES OUTPUT` writes a census sites file with its `watch` ranges taken from the same extents.
- `//replacement/saclac:saclac-extent-refs --listing NAME=PATH ... --output PATH` reports every branch, data word, `movw`/`movt` pair and PC-relative address computation whose target lies inside the extents, and which of them start outside.
- `//replacement/saclac:saclac-placement-tests LINKED_BIN SYMBOLS DISASM SECTIONS` admits the linked image and runs the refusal controls.
- `//replacement/saclac:stage-saclac ENCODER REBUILD DECODER SOURCE_DAT IMAGE5 LINKED_BIN SYMBOLS DISASM SECTIONS SCRATCH_DIR OUT_IMAGE5 OUT_DAT OUT_CONTRACT` admits, installs and stages record 5 (13 positional arguments).
- `//replacement/saclac:saclac-census-compare STOCK_JSON CANDIDATE_JSON CONTRACT_JSON OUTPUT_JSON [MILESTONE_PHASE]` compares two census reports and reports every machine's sequence, the dispatcher-entry identity, the trap fetches and, when both reports carry the named milestone, every machine's sequence up to each side's first sighting of it (default `shooting-menu`).

The census sites file keeps the watch points, the action ranges and the `dispatch` table addresses; the `watch` ranges are generated from the extents by `//replacement/saclac:saclac-census-sites`.

Admission is split between the binary and the source. `saclac-placement-tests` checks from the ELF and the bytes that every owned symbol and allocated section lies inside the two extents, that no section is writable or NOBITS, that the two entry veneers sit at their stock addresses, that the count arrays match the declared table extents, that every literal pool entry names an owned address or a declared external or stock array, that every direct branch targets owned instructions or a declared external, that no store uses a base a code literal loaded, that control never enters a data word, that every function's frame comes from its prologue, that the direct call graph has no cycle and no chain above 1,024 bytes of task 43's 0x1000-byte stack, and that unused extent bytes are the trap word. A register branch or call is admitted only inside the symbol extent of a function compiled from `src/stock.rs`; the placement check does not re-derive the target's provenance from instructions. The source carries that provenance through `StockCodeWord`. Memory safety inside owned code rests on the compiler and the bounded types: the crate root denies `unsafe_code`, `src/engine.rs` and `src/machine0.rs` forbid it, and every index is a bounded type parsed at entry. The comparison suites exercise retained callers' entries and the census watches for fetches in trap-filled retired bytes. `src/stock.rs` is the crate's only module allowed `unsafe`, whose blocks are:

| Block | Invariant |
| --- | --- |
| `read_word`, `read_word_indexed`, `read_half` | The address is a declared stock array plus a 4- or 2-byte-scaled `Machine` index, so it is inside that array and aligned for the width. |
| `write_half` | The address is the rows or states array plus a 2-byte-scaled `Machine` index; these are the only stock-memory writes. |
| `call3` | The word is the declared trace external `0xf46c38`, a stock function entry with the `(u32, u32, u32) -> i32` signature. |
| `RawCells::action`, `RawCells::next` | The base is the machine's cell-table word; `CellIndex` is below the declared cell count. |
| `RawWords::word` | The base is the machine's action or second table word; `WordIndex` is below that table's declared count. |
| `enter_word` | The word is a nonzero word read from a declared machine table below its count, and stock code words take the four-word signature with the table base in r2 and the word in r3. |

The shim rows are in [the register](shims.md#saclac).

## Native rewrite qualification

For an applicable native-only increment, run the native SDK and runner suites plus the affected caller's qualification command:

```sh
devenv shell -- env XM1_EMULATOR_SLOTS=1 host-build test --jobs=2 --local_test_jobs=1 \
  //emulation:native-sdk-tests //emulation:native-runner-tests
```

`//emulation:native-sdk-tests` selects the native SDK build rather than unrelated SDK executables and harnesses. Keep `//emulation:fujimod-xm1-tests` and the complete existing qualification at the full-integration boundary. The native pair does not replace family, subsystem, system, control or hardware checks. Reuse compatible completed observations; adopting this tooling alone does not require replaying them.

The current `host-build` automatically reports the kernel-sampled lock holder on first contention and owner changes. Use its PID, workspace/output-base context and existing `command.log` pointer before doing manual process archaeology. Unavailable or raced metadata is not evidence that the lane is free, and elapsed time does not authorize stopping a holder. The [build command guide](../build-support/README.md#commands) owns diagnostic details, resource limits and the real-wrapper checks. `host-build run` releases the build lock before executing its target; emulator targets then take their own slot.

An older topic checkout may still provide an older launcher. Use the current qualified `host-build` executable through `devenv shell` from the worker checkout with its usual output base. Resolve it from current main only when that checkout is ready for Nix evaluation; otherwise use the integration owner's frozen launcher path. Keep the worker's source and working directory; do not change SDK identities merely to adopt admission. Each topic's emulator binary retains its compiled policy. Use the qualified shared wrapper or adopt the current admission modules before requesting the new RAM and swap caps; setting an environment variable does not upgrade an old binary. Current defaults are 12 GiB RAM plus 8 GiB swap for builds and native suites, and 8 GiB RAM plus 8 GiB swap for full-system runs, within the shared 64 GiB combined reservation budget. Keep completed and healthy running cohorts bound to their original scopes.
